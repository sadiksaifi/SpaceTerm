# Install and pair Machines from their own command line

The primary remote setup path runs on the Machine itself: `install.sh`, `spaceterm setup`, then `spaceterm pair`. Another device joins the Invitation Link through the desktop's Add Machine or `spaceterm machine add`. [ADR 0029](0029-enroll-remote-servers-through-add-server.md) owns enrollment trust and the optional desktop SSH Setup method.

Setup offers Linux linger authorization, installs the service from the launcher's installation, starts SpaceTerm Core unless deliberately stopped, and sets Network Access. [The setup handler](../../crates/spaceterm-cli/src/admin/setup.rs) reports its steps and changes only preferences its flags name. `network` changes Network Access later, also from a Paired Device, under [ADR 0057](0057-administer-servers-over-the-service-lane.md). Without a terminal, Network Access must be explicit. [ADR 0030](0030-start-servers-at-boot-independently-of-clients.md) owns startup policy, when linger is required and the Mac GUI-session requirement. `spaceterm uninstall` removes the service under [ADR 0054](0054-use-one-headless-executable.md), and `install.sh --uninstall` runs it.

`pair` prints the Invitation Link first and, by default, a compact Unicode QR code encoding that same one-use, five-minute invitation. There is no QR flag. The QR rendering requires stdout to be a terminal with a known size that fits the code and its four-module quiet zone without wrapping or scrolling, including room for the waiting message, the longest Comparison Code prompt and code entry, a non-dumb terminal type and a UTF-8 locale. The encoder starts at low error correction to choose the smallest version, strengthening correction only when that version still fits. It uses basic indexed ANSI black-on-white colors, supported by color terminals including GNU Screen without RGB support, so both terminal themes remain scannable. When rendering is unavailable, stdout contains the link alone, without a warning. Neither rendering is retained in logs, files or diagnostics. The command waits for that invitation's exact claim. It uses the invitation management contracts in [ADR 0029](0029-enroll-remote-servers-through-add-server.md). `--address ADDRESS[:PORT]` supplies the advertised authority. [The pairing flow](../../crates/spaceterm-cli/src/admin/pair.rs) polls every two seconds with its own invitation ID and waits no longer than five minutes for a claim. The person types the Comparison Code displayed on the joining device. Comparison Code entry stays within the invitation's lifetime and ends on EOF or interruption under [ADR 0055](0055-define-the-cli-output-contract-and-scope-model.md). A wrong code rejects the claim. A failed attempt tries to withdraw its invitation, including when stdout closes; that outcome follows ADR 0055's silent broken-pipe exit contract. Approval prints `Paired <device>.` on stderr. JSON, no-input mode or absence of terminal input and stderr fails before creating an invitation. JSON output retains the existing `interaction_required` envelope and contains no QR rendering.

`machine add` reads the link from stdin or a hidden prompt, never from arguments. `--trust` authorizes noninteractive enrollment; the joining client still displays its authenticated Comparison Code for approval on the Machine itself. `--address` replaces only the invitation's endpoint and preserves its Machine ID, certificate and proof-key pin. CLI Saved Connections and credentials stay separate from the desktop's. One Machine may have several CLI Saved Connections, for example one over the LAN and one over a tailnet; their names are the values of `--machine`. [The connection handler](../../crates/spaceterm-cli/src/connection.rs) owns consent and output; [shared enrollment](../../crates/spaceterm-connections/src/enrollment.rs) persists exact cancellation authority before any network effect and commits the Saved Connection only after enrollment succeeds.

`machine rename OLD NEW` changes only the CLI's Saved Connection name. The desktop's separate records stay unchanged. [The CLI connection store](../../crates/spaceterm-connections/src/store.rs) checks the exact old name and new name's availability under its transaction lock, including names reserved by enrollment. A name already in use, including the old name itself, exits 2; an unknown old name exits 4. Either refusal leaves the saved document unchanged. A successful rename invalidates that route's removal previews and preserves its route ID, endpoint, pairing, Machine ID and opaque credential reference. It neither opens the credential store nor contacts the Machine.

CLI connection-store mutations use [bounded transactions](../../crates/spaceterm-connections/src/store.rs) for rename, enrollment, removal and restricted cleanup. Each transaction retries nonblocking lock acquisition on the caller's thread within its deadline and cancellation check, then checks both again immediately before publication. Expiry or interruption before publication leaves the saved document unchanged and reports `timeout` or `interrupted` under [ADR 0055](0055-define-the-cli-output-contract-and-scope-model.md). Interrupted enrollment cleanup retains its existing five-second grace period.

Confirmed connection removal removes the active local record before attempting revocation on the Machine. Restricted self-revocation and credential cleanup remain pending until confirmed. Later `machine add` and `machine remove` commands retry them. `machine list` reads active and pending records and held counts without opening credentials, admitting a connection or retrying cleanup. [ADR 0038](0038-unpair-devices-without-blocking-local-connection-removal.md) owns exact revocation and enrollment cleanup.

[ADR 0004](0004-resolve-application-directories-by-xdg-convention.md) owns credential storage and its requirements for the CLI's client role and SpaceTerm Core's account service.
