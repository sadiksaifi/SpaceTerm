# Unpair devices without blocking local connection removal

Unpair Device is the single action for removing a device-server pairing; a separate Forget Server action is excluded to keep removal in one workflow. After the person confirms, it may target the device performing the action, including the server's last Paired Device.

For self-unpair, the initiating client immediately removes the target server's Workspace Attachments and any saved remote connection and ends ordinary use of that pairing, independently of server reachability. A permanently deleted host must not leave an obsolete connection in the sidebar or saved-server list. Unpairing another device leaves the initiating client's connection and Workspace Attachments intact. Cleanup permits an empty client view without creating a replacement Workspace or killing server-owned work.

The server durably records revocation, closes every connection authorized by the target device, and releases its Pane control without stopping the server or its Terminal Sessions. Revoked credentials cannot authenticate or resume previous control grants; other devices and the target device's access to other servers are unaffected.

Local removal and server-confirmed revocation have distinct outcomes. If the server is unreachable or its acknowledgement is lost, local removal completes while a durable background revocation request remains pending across app restarts. A dismissible notice in the existing Servers Settings Section explains that the connection was removed and server confirmation is pending; dismissing the notice hides it without cancelling retries. No additional removal button or Settings Section is introduced.

The retry task retains the route and native credential material needed to finish revocation, restricted to that operation rather than ordinary terminal use. Retries follow [ADR 0037](0037-resolve-shared-mutations-at-the-server.md) and target the original authenticated server identity and pairing; a changed SSH destination or a later pairing cannot redirect the request. Completing an old request must not remove a newer pairing's credentials, saved connection, or attachments, another server's credentials, or any shared device identity key. Confirmed completion clears the task and its retained pairing credential material.

Retries never recreate removed connections, attachments, or Pane control and do not implicitly Start Server, update or restart either side, or enroll a revoked device again. Authorization or compatibility failures leave server revocation unconfirmed. Deliberate pairing follows [ADR 0029](0029-pair-clients-automatically-during-ssh-bootstrap.md). Local discovery continues to reuse the existing server under [ADR 0033](0033-reuse-one-server-across-headless-and-desktop-installations.md), without restoring ordinary access after self-unpair.
