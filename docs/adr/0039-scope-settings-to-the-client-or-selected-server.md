# Scope Settings to the client or selected server

Client Settings remain specific to the client device, while Server Settings belong to one SpaceTerm Server. One Settings Window retains the existing client preference sections and adds a searchable Servers section. It lists the account-local server first and then every saved SSH connection. The selected server's detail names that machine and shows its connection method and authority, direct-network pairings, relevant operating-system authorization, status, compatibility, server management and Server Settings, so every operation identifies the machine it affects.

End All Sessions follows [ADR 0048](0048-end-all-sessions-from-the-selected-servers-settings.md).

Interface, Font, Themes, Keybindings, clipboard preferences, Git presentation preferences, and client update preferences remain client-owned. Clipboard preferences govern that client's clipboard under [ADR 0013](0013-order-terminal-clipboard-access-by-session-focus.md) and the Pane control rules in [ADR 0022](0022-give-one-client-control-of-each-pane.md). GitHub CLI authentication and Pull Request lookups retain the client-local ownership in [ADR 0018](0018-read-repository-status-by-running-git-and-the-github-cli.md).

Git discovery and execution use the owning server's tools and filesystem. New Worktree Location is a server-owned preference shared by its authorized clients, and its template expands and validates in that server's filesystem context. Settings edits it through the selected server's own connection, and only while that server is connected. Legacy Worktree Location seeds a new local server once and never overwrites an existing server. System Permissions remain operating-system capabilities on the machine where the terminal program uses the protected resource, following [ADR 0014](0014-guide-permission-setup-on-system-settings.md); a client's permission setup cannot grant another machine's permissions.

Status shown for a connected or requested route comes from the worker that owns that connection intent under [ADR 0045](0045-freeze-terminal-screens-while-reconnecting.md). Constructing, rendering, searching or opening the Servers section reaches no remote host. Check Status is the explicit request for one fresh observation of an otherwise inactive saved connection. It may obtain SSH interaction because the person asked, and it connects, starts and installs nothing and leaves connection intent unchanged.

The account-local server needs no pairing and offers no removal. Removing a saved SSH connection is immediate. It removes the connection's presentation and ordinary reconnect intent, and it leaves SSH account access, the server, its Terminal Sessions and restricted pending originals in place under [ADR 0029](0029-pair-clients-automatically-during-ssh-bootstrap.md). Direct-network Unpair Device follows [ADR 0038](0038-unpair-devices-without-blocking-local-connection-removal.md).

Advanced import, export, and reset operate on Client Settings and installed Terminal Themes in the Settings Document, whose schema stays 7. Saved connections and their retained intent, server identity, device credentials and authorization, pending operations and unpair requests, Workspace Attachments, Client View State, server-owned Workspace organization, Server Settings, and deliberate Stop Server state remain outside the Settings Document, so preference transfer or reset cannot change those lifecycles. Server update restarts retain the confirmation requirement in [ADR 0034](0034-confirm-server-update-restarts-and-explain-incompatibility.md).
