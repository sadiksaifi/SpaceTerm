# Derive agent identities at admission

An Agent Name gives a recurring automation actor its own Pane control and operation history without another enrollment. Names follow `^[a-z0-9][a-z0-9-]{0,31}$` and are intended for reuse. `--as` or `SPACETERM_AS` supplies the name. Admission derives the effective identity as `SHA-256("spaceterm.agent.v1" || base_client_id || agent_name)` on local and paired routes. [ADR 0028](0028-use-spaceterm-protocol-over-every-client-connection.md) owns its authority and pairing boundary; [ADR 0022](0022-give-one-client-control-of-each-pane.md) owns Client Name presentation.

The CLI retains a base identity per server route in its own `clients/cli/` namespace. Each effective identity has separate Workspace Attachments, retained inventory and journals under that route. CLI connection-store updates lock the complete read-modify-write transaction, so concurrent enrollments cannot overwrite each other.

A shared mutation holds the existing Original Operation writer lock from sequence allocation through dispatch, reply, journal retirement and acknowledgement. Mutations under one identity run one at a time; distinct Agent Names allow independent writers. Run receipts use a separate lock and journal. Terminal I/O does not take the shared mutation lock. Process exit retains Pane control; `pane release` relinquishes that identity's grant.

Before its own work, each command that connects settles leftover journals for every CLI identity held for that server, skipping locks held by active processes. Recovery resolves original operations and runs without replaying input or destructive dispatch. Structured recovered results carry their operational data; warnings stay bounded. Status and connection inventory expose held counts across agent-name reuse. [ADR 0037](0037-resolve-shared-mutations-at-the-server.md) owns server outcome retention.

Creation with an Agent Name gives the agent control. Creation from a validated Terminal Session without an Agent Name assigns the origin Pane's current controller; the server sends Reveal only to that controller. The desktop applies Reveal only while the origin is still focused and no newer selection exists. Other CLI creation leaves the new Pane unclaimed. These choices use the control policies in ADR 0022 and preserve each client's view under [ADR 0041](0041-keep-each-clients-view-independent.md).
