# Own status controls in the desktop client

The desktop SpaceTerm Client owns its windows and native status item in one process. The menu bar/status area is part of that client, with no separately installed status application or helper registration. The installed Preflight and Release SpaceTerm Server remains independently supervised and headless under [ADR 0030](0030-start-servers-at-boot-independently-of-clients.md).

Command-Q and equivalent application Quit requests present a three-choice alert titled "Are you sure you want to quit?". Its choices, top to bottom, are "Quit SpaceTerm" (default), "Cancel", and "Quit SpaceTerm Completely". Linux uses its host's status-area terminology. Quit SpaceTerm closes every client window and removes Dock presence while keeping the same client running in the menu bar or status area. Quit SpaceTerm Completely exits the client and removes its status item. Cancel leaves the application unchanged. The alert explains these consequences. Initial keyboard focus, Return, and Space choose the default; Escape cancels; only its own button quits completely.

Without an available status area, the default reads "Keep SpaceTerm Open" and leaves the windows open so the client remains reachable, and the alert says so. A windowless client presents the choice in a temporary window that creates no Workspace and closes after the answer.

The application menu has one "Quit SpaceTerm" item with Command-Q, which presents the same alert. The status item's own Quit exits directly. Completing an explicit Quit choice exits without presenting the chooser again. This replaces the earlier pair of "Close All Windows" and "Quit SpaceTerm" menu items ([issue #624](https://github.com/sadiksaifi/SpaceTerm/issues/624)). Opening SpaceTerm restores the existing client's windowed presentation. For installed Preflight and Release, both dismissal choices leave the independent server and its Terminal Sessions running; Stop Server remains a distinct confirmed operation.

An installed client crash may remove the status item but leaves server-owned work running. The supported service-control fallback remains usable without the client or a status-area host. A later desktop installation reuses an existing headless installation under [ADR 0033](0033-reuse-one-server-across-headless-and-desktop-installations.md). The future general CLI in [issue #596](https://github.com/sadiksaifi/SpaceTerm/issues/596) records intent only and does not expand this control surface.

For source Development, the development command owns the complete run under [ADR 0030](0030-start-servers-at-boot-independently-of-clients.md). Closing windows keeps that run available in the status area. Complete client exit or ending the command ends its foreground Server and Terminal Sessions.
