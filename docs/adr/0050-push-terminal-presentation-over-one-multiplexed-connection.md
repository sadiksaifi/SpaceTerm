# Push terminal presentation over one multiplexed connection

Each desktop SpaceTerm Client holds one full-duplex work connection per SpaceTerm Server, except for the uses [the local server workflow](../local-server.md#connections) names. Requests carry identifiers, so several can be in flight at once. The server pushes replies, terminal presentation, Pane events, native effect requests and Workspace Inventory as they happen. No Pane waits for another Pane's work.

The server writes pings first. Replies, Pane events, Workspace Inventory and terminal presentation follow in publication order. Bulk transfers such as Scrollback pages, images and large replies come last, in bounded chunks, so they cannot delay a keystroke's echo. The client writes requests, terminal input, frame acknowledgements, views and pings in one queue, in the order it made them, so a claim never overtakes an earlier request and input never overtakes its claim. Edit acknowledgements, native effect completions and cancellations follow that queue. A paste travels as consecutive input messages of at most 60 KiB each.

After work admission, every work message uses postcard in one length-prefixed framing. Admission, pairing and the [service lane](0057-administer-servers-over-the-service-lane.md) use JSON. The encoding spike measured postcard within 10% of a hand-written encoding. Future mobile clients will embed the same Rust client, so a text format would buy no portability. Screen rows travel as style runs against style and link tables that persist across a Pane's frames. The server encodes only the rows the Terminal Emulator reports as damaged, without patching the engine, and reports a scroll as a shift when row hashes match the previous frame.

The server keeps the authoritative screen and Scrollback of each Terminal Session. The client declares a maximum frame rate of 60 or 120 Hz for each Pane it shows. The server publishes the first output after idle immediately. During continued output, it publishes once output has been quiet for 4 ms or one frame interval at that rate has passed, whichever comes first. A publication never follows the previous one sooner than one frame interval. It respects synchronized output (DEC mode 2026). Each Pane has at most one unacknowledged frame, and newer state replaces pending state, so a slow client receives the latest screen rather than a backlog. Each frame reports the latest input it reflects. A Terminal Session wakes the I/O thread of each connection that presents it, and that thread captures and publishes its screen under the server lock. No other server thread wakes for an echo. A Terminal Session that no connection presents wakes the server's host thread instead. A hidden Pane receives no frames. A new claim, a lost baseline or a reconnect receives a complete screen.

Each client keeps a Scrollback Cache for each Pane. Wheel scrolling, Scroll Commands, Selection, copy and Terminal Find run over that cache, so within the cached rows they cost no round trip and each client's view stays independent under [ADR 0041](0041-keep-each-clients-view-independent.md). Opening Terminal Find loads older history in the background. Rows are numbered within a history epoch, so the server discarding its oldest rows never renumbers the rest; rewrapping or resetting history, or a taller screen taking rows back from it, starts a new epoch. A reconnect keeps the cache only when the Terminal Session is unchanged and its Scrollback has not been cleared. While the program uses the alternate screen or mouse reporting, wheel and pointer input go to the program. Assistive technology reads the rows this client shows and its Selection; a Selection made through assistive technology is applied on the server.

The server pushes Workspace Inventory as whole snapshots, and each new revision replaces any revision not yet written. Deltas wait until measurement shows a need. A shared edit takes one round trip: its reply carries the validated outcome after the revision that contains it. Acknowledgements are cumulative and have no direct reply; [ADR 0058](0058-derive-agent-identities-at-admission.md) defines how the CLI confirms their application before forgetting journal entries. The server keeps its disk syncs for durability and runs them off the request path. Writes follow commit order, and one write retains every earlier revision. Each write syncs only the new record and its directory. A revision reaches clients only once it is on disk, so no client acts on organization the server could still lose. The reply to an edit follows the revision that holds its outcome. A deletion ends Terminal Sessions only once it is on disk. An edit that waits for a Worktree write is one request, whose reply arrives when the write settles. A directory or Worktree read is one request too. The client sends `Cancel` to abandon a read and never polls one. The thread that runs a read wakes the server when the read settles, so the server never polls one either. The client presents the edit optimistically under [ADR 0037](0037-resolve-shared-mutations-at-the-server.md), so it never waits for a sync. One server lock orders Pane state, with encoding and disk syncs outside it, until measurement shows contention.

While nothing changes, a client presenting Panes and its server do no periodic work and send each other nothing but pings. A Pane waiting at the Restored or Takeover screen asks the server again only when a pushed revision changes its control facts, the person acts, or the link ends. The server reads a repository's Git facts again only when its git directories change, a command finishes in a Pane in that repository, or such a Pane gains focus. It never watches a work tree, so an edit made outside SpaceTerm appears at the next of those. A read that changes nothing publishes nothing.

Connection health comes from traffic and pings on the live connection, never from polling or extra connections. Silence or stalled writes end the connection, and the client recovers under [ADR 0045](0045-freeze-terminal-screens-while-reconnecting.md). After reconnecting, a Pane accepts input only once its control grant and a complete screen have been applied.

Account-local connections use the Unix socket, because a shared-memory spike measured a gain under 0.1 ms. Paired connections use QUIC under [ADR 0052](0052-carry-paired-connections-over-quic.md). Both sit behind one carrier interface. [ADR 0035](0035-negotiate-one-protocol-major.md) owns the work major and admission version policy. [ADR 0027](0027-trust-paired-clients-equally.md) and [ADR 0028](0028-use-spaceterm-protocol-over-every-client-connection.md) own admission authority, pairing, pinned certificates and proof keys.

[ADR 0051](0051-predict-typed-characters-at-the-shells-line-editor.md) owns Line Mode and Predictive Echo from the frames' input serials. Pane control follows [ADR 0022](0022-give-one-client-control-of-each-pane.md).
