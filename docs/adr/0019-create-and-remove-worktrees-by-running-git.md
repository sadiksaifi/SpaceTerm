# Create and remove Worktrees by running git

SpaceTerm creates and removes Worktrees by running the person's own git with the hardening Repository Status reads use, so git stays the one owner of the repository's administrative files. These are SpaceTerm's only repository writes, and they happen only when the person confirms one in a dialog. Writes use branches already fetched, and git itself never fetches, because every transport is disabled. They work only in local Workspaces. Hooks never run, so a `post-checkout` hook's setup does not happen. Clean and smudge filters run under the person's configuration, as they do for reads, so a filter such as Git LFS can download content while a Worktree is created. A started write runs to its end. Removing a Worktree passes `--force` only after the person confirms an alert that names what it deletes: uncommitted changes they chose to discard, or the checkouts of the Worktree's submodules, which git removes only with `--force`.
