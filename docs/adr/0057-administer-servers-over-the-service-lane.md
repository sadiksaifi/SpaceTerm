# Administer servers over the service lane

Status, Stop, Restart, Update and Change Network Access use a service lane on the authenticated account-local or paired connection. [ADR 0027](0027-trust-paired-clients-equally.md) owns authority and machine-only actions. `server unpair` accepts only the local route, including when the target is another Paired Device. End All Sessions uses account-local work admission under [ADR 0048](0048-end-all-sessions-from-the-selected-servers-settings.md). [CLI route validation](../../crates/spaceterm-cli/src/connection/route.rs) rejects a remote route before credential or transport access.

The lane uses bounded length-prefixed JSON through the admission preamble, independently of the work protocol major. An incompatible work client can therefore update a server and settle the same operation after reconnecting. This is one lane on the existing transport. [ADR 0035](0035-negotiate-one-protocol-major.md) owns its version policy. [The lane contract](../../crates/spaceterm-server/src/service/lane.rs) includes the admitting `boot` in `Accepted` and the candidate's `to_major` in update effects. Clients use those fields to check replacement and warn when work commands will need a matching client.

[The direct host](../../crates/spaceterm-server/src/direct/host.rs) registers a paired service lane with its pairing's connections before the first request. The registration lasts for the lane's whole life. Revoking the pairing severs the lane. A Network Access change that starts a new listener generation also severs it. [The lane server](../../crates/spaceterm-server/src/service/lane.rs) revalidates the pairing and listener generation before each read and again before answering each request. Host stop severs a waiting lane read before joining its thread.

A lane Status or Check request reads facts without activation recovery. [The local CLI update entry point](../../crates/spaceterm-cli/src/server/update.rs) settles activation before opening the lane only without `--check`. [`server start`](../../crates/spaceterm-server/src/service.rs) also settles interrupted activation. `server update --check` is passive. Unreachability does not establish that a server is stopped; any last-known connection time is explicitly dated under [ADR 0058](0058-derive-agent-identities-at-admission.md). Update delivery uses a signed target feed fetched by the server or a paired upload. The server verifies the candidate under [ADR 0040](0040-keep-one-server-runtime-version-active.md).

The server feeds are `spaceterm-darwin-arm64.json` and `spaceterm-linux-x86_64.json`. Each feed and archive has a raw 64-byte detached Ed25519 signature. The feed's archive signature is base64 inside JSON. [Release signing](../../mise-tasks/lib/spaceterm_tasks/release.py) writes the schema-1 identity, target, version, publication time and archive description; [feed verification](../../crates/spaceterm-server/src/service/feed.rs) authenticates that document before downloading its named archive.

A running server's preview binds an actor, action, server, boot, service state or activation approval, and exact affected Terminal Session set. [The lane observation digest](../../crates/spaceterm-server/src/service/lane.rs) hashes those service observations and the sorted Session IDs when the service is running. Update and Return bind the activation approval's confirmation digest; Stop and Restart bind the retained service state. The server retains at most 16 random `c1-` tokens, each redeemable once by its actor and action within ten minutes. Issuing past capacity drops the oldest token. A server restart loses the registry. [The token registry](../../crates/spaceterm-server/src/service/tokens.rs) refuses unknown, spent, expired or mismatched tokens as `changed`.

Offline Update or Return on the server's own machine, Unpair and End All Sessions use `c1-` tokens instead of a server-held token registry. [Offline tokens](../../crates/spaceterm-cli/src/server/offline_token.rs) carry their issue time and a digest binding that time, purpose and exact observation. [Offline Update](../../crates/spaceterm-cli/src/server/update.rs) uses the activation or return approval digest. [Unpair](../../crates/spaceterm-cli/src/server/unpair.rs) hashes the server ID, exact pairing ID and device public key. Each command recomputes its digest before acting. These tokens expire after ten minutes. Expiry or a changed observation reports `changed`.

Admission revalidates the preview and durably records the operation while holding the pane-service lock. It sets the membership fence under that same lock. While any admitted Stop, Restart, Update or Return remains unsettled, [the host request path](../../crates/spaceterm-server/src/host.rs) refuses every `Claim` with `ServiceBusy`, exposed as `service_busy`. This includes reattaching to an already running Terminal Session. Organization edits that start no Terminal Session remain available. This is the v1 membership policy. Repeating the operation ID resolves that record and never repeats the action. The lane writes `Accepted` before launching the helper. A failed write still launches the durably admitted operation.

The approved runtime launches a transient helper outside the server service's process tree: a collected systemd user unit on Linux, or `posix_spawn` with `POSIX_SPAWN_SETSID` on macOS. It inherits no server sockets or lock descriptors. [The helper](../../crates/spaceterm-server/src/service/helper.rs) holds `service-helper.lock` for its whole run, reads only its admitted record and runs the same native operation as a local caller under the service lock. A free helper lock proves that no helper is acting when [ledger settlement](../../crates/spaceterm-server/src/service/operations.rs) examines an interrupted operation. No permanent helper is installed.

The durable ledger records admission, launch, execution and the terminal outcome. Startup recovery marks an admitted operation that never launched as not performed. Interrupted Update resolves through activation recovery; an unprovable Stop or Restart stays unresolved. A changed boot alone is not a generic success receipt. Unacknowledged records remain until the same actor acknowledges them. Revoking the pairing deletes its settled records. An unsettled record stays, orphaned, until its helper or start-up recovery settles it, and the ledger then deletes it. [The shared revocation path](../../crates/spaceterm-server/src/direct/host.rs) invokes [the host's ledger cleanup](../../crates/spaceterm-server/src/host.rs) for both account-local and paired-wire revocation. The ledger refuses new admissions at capacity instead of expiring records by age.

[The lane client](../../crates/spaceterm-server/src/service/lane/client.rs) replaces a lane idle for at least 20 seconds before sending Execute. After a transport loss once Execute was sent, it follows the same operation ID. Before interruption, it can repeat Execute to recover the existing admission. After interruption, it only resolves that ID under [ADR 0055](0055-define-the-cli-output-contract-and-scope-model.md). Restart and Update resolve their receipt before reporting completion. A Stop that cannot reconnect reports the lane outcome `Shutdown`, exposed as `observed: shutdown` with exit 7, because losing the connection cannot prove native cleanup. On the server's own machine, [local Stop confirmation](../../crates/spaceterm-cli/src/server/lifecycle.rs) reads the ledger and exits 0 when it records completion. A later lane connection after local Start settles and acknowledges a retained receipt. [ADR 0034](0034-confirm-server-update-restarts-and-explain-incompatibility.md) owns activation confirmation, cross-major candidates and return to a previous runtime.

## Network Access changes

`spaceterm server network` changes Network Access through the lane, on the account-local or paired route. `server setup --network` stays on the server's own machine. [The lane's Network Access module](../../crates/spaceterm-server/src/service/lane/network.rs) owns the plan, its refusal and its observation digest. [The direct host](../../crates/spaceterm-server/src/direct/host/network_change.rs) plans each change under its direct-network lock. A plan holds Network Access before and after the change, whether the listener starts over and so ends every paired connection, and which connected Paired Devices lose their route. A connection keeps its route when the new listener serves the server address it reached. The preview reports the caller's own connection as `stays_connected`, `reconnects` or `disconnected`.

A paired caller's change that keeps no connected device's route is refused as `disconnects_every_device`, before any token is issued. Turning Network Access off is always such a change. The server cannot see the routes of devices that are not connected, so they do not count. The account-local route may make any change.

The token binds the server run, the request, both settings, the listener generation and every reported effect. Execute plans again under the direct-network lock, checks the token's digest and the refusal, and admits the change in the ledger. The lane writes `Accepted`, plans once more, claims the record and applies the change in-process with the same `SetPolicy` request that `server setup --network` sends. No helper runs. A Network Access change ends no Terminal Session, so it sets no membership fence. A server that ends between the claim and the recorded outcome leaves the record unresolved; one that ends before the claim leaves it not performed.

When the change ends the caller's lane, [the lane client](../../crates/spaceterm-server/src/service/lane/client.rs) reconnects and resolves the same operation ID, as it does after a Restart. [The command](../../crates/spaceterm-cli/src/server/network.rs) then reads Network Access back over a new connection. A caller that lost its route cannot reconnect, so the command reports `outcome_unconfirmed` and exits 7 when its 30-second wait ends. Its settled record stays on the server until that device acknowledges it on a later connection or is unpaired.
