01

Why we are doing this

The build works. What follows is about how it reads, and about four faults that were structural rather than cosmetic.

Chrome was proportional to nothingEvery Pane carried a 32px filled header saying N · SpaceTerm, which is the Workspace name you can already read in two other places. Five Panes cost 160px of vertical chrome carrying no information.
Focus was nearly invisibleA 1px border colour change and a 12px label weight. In a tool where keystrokes go somewhere, that is the single most important thing on screen and it was the quietest.
Two menus, one shape, different meaningsThe Pane menu and the Tab menu were the same four rows differing only in what the last one closed, reachable from a hover-revealed ⋯ per Pane and a global ⋯ whose Split actions had no defined target.
Half the window ignored activationTabManager::render discards its Window, so on deactivation only the 240px under the sidebar dimmed and everything right of it stayed lit.

Two things came out of the discussion that were worth more than any individual fix. First, that the original edge-to-edge structure was right, and an excursion into floating cards on a ground was what made the app start reading as Electron. Second, that a strip listing the Panes of a Tab you are already looking at is restating the layout, which is why no amount of restyling made it feel earned.

02

Principles

These decide the answers, so disagreements should happen here rather than per widget.

1Regions meet, and are square. Nav bar, sidebar and terminal share edges divided by 1px lines. No gutters, no ground between them, no rounded region corners, no shadows on content. The window radius is the only one that touches a region.
2Controls sit inside regions, and are round. Tabs, the lit segment, sidebar selection, icon buttons: 5–7px and a fill. Finder is exactly this, a square region with rounded selection inside it.
3Only overlays float. Menus, popovers, dialogs, the combo panel. If primary content floats, the overlay layer has nowhere left to go.
4A control appears only when it can do something no other visible control can. At count = 1 the Zoom and Close icons withdraw rather than sitting disabled.
5Chrome is quieter than content. 10.5–12px chrome against 12px terminal mono. The frame never competes with what it frames.
6Colour is an exception, not a system. One accent with one job, amber reserved for remote and attention, red only where data is at risk.
7Animate geometry, never colour. Things that move get a short curve; things that change state just change.
8Never state a convention. No ↵ Open legends, no keyboard hints in list footers.

New Workspace flows, then sticks

It sits directly under the last Workspace while there is room and pins to the bottom once the list fills the column, Chrome vertical-tabs style. Its 28px is always reserved when deciding whether the list overflows, so adding the row can never cause the overflow that moves the row. A 16px ground-to-transparent fade sits above it when pinned, rather than a divider, because a hairline there would put a drawn line back into a design built on not having them.

What was wrong with the old footer: it was a verb wearing the costume of a noun. Every other row is a thing you select and live inside; that one was an action opening a modal flow, drawn at the same size in the same pill. It also floated in dead space once the divider went, and it carried a ⌘N label, which is menu vocabulary in a list row.

Tab strip

A Tab is a cell attached to the terminal below it. Its Panes are segments inside that cell, always visible, each clickable and closable. This is the piece that took the most iterations, so the reasoning is recorded below the drawings.

How it is built

The joinThe active cell is surface coloured with three inset edges and no bottom edge, and a 2px surface strip paints over the nav rule beneath it. The Tab is physically continuous with its terminal. This is why it cannot read as a segmented control: a cell joined to the thing it names is not a mode picker.
Never clip the celloverflow:hidden on the cell clips the element that covers the nav rule. Segments carry their own radius instead.
The lit segmentFills the cell's content box, 5px radius on all four corners — the cell's 6px minus its 1px edge, so the curves are concentric. The 1px showing above and below is the cell's own edge, which is what makes it read as part of the cell rather than a pill in it.
Unfocused segments55% opacity, the same dimming an unfocused Pane uses in the terminal. The strip and the content agree about what focus looks like.
Ticks1px, 12px tall, between adjacent unfocused segments only. A lit segment needs none; its own edges do the dividing.
CloseOn the hovered segment only, with its 13px space permanently reserved so nothing shifts and four crosses are never on screen at once. On a one-Pane Tab it closes the Tab.
3Hard cap on inline segments. Four plus their closes plus a Tab label crosses the width where labels start truncating, and a truncated Pane label is worse than a count. The Focused Pane always shows, plus its neighbours in layout order, so the Pane you are in is never the one hidden.
Overflow+n with a chevron at the trailing end inside the cell, so it stays attached to the Tab it belongs to.
Inactive TabsLabel, count and the same chevron. Their Panes are one click away without spending strip width on Tabs you are not in.

Segment labels

First match wins. Directory labels help distinguish Panes as the user navigates. Each Pane can work in a different Current Directory.

1Explicit title set by the program through OSC 2 or OSC 1, or a Pane the user renamed.
2Foreground process when it is not the login shell: cargo build, nvim. Command plus first argument.
3The Pane's Current Directory, shortened for display. It is independent of the Workspace name and any Pinned Directory.
4The shell. Four idle Panes at the root reading zsh zsh zsh zsh is honest; they genuinely are the same thing, and they are in layout order.
Separator> between place and process, as in crates > cargo build. Not a middle dot.

Click semantics

Segment in the active TabFocus that Pane.
Segment in an inactive TabActivate that Tab and focus that Pane, so one click lands where you pointed.
Tab label, not a segmentActivate the Tab and restore its last Focused Pane. Nothing is re-focused against your will.
While a Pane is ZoomedDrop the zoom and focus that Pane. Segments keep showing every Pane while zoomed, which is what makes zoom a view rather than a mode.
Middle-clickClose that Pane.
Right-click a segmentThe Pane menu. Right-click a Tab label gives the Tab menu, so the two menus finally have distinct targets.

08

Focus

Expressed without drawing anything, because every drawn treatment tried — underline, full border, seam lighting — read as geometry laid over the content.

VeilUnfocused Panes render at 60% opacity. Opacity, not a tint, so it needs no token and works on any theme. Ghostty and iTerm both ship this.
CursorUnfocused Panes draw a hollow outline cursor. Every terminal on every platform already means exactly this by it.
CaptionThe focused caption is at full contrast, others dim, and only the focused Pane shows its icons at rest.
In the stripThe same 55–60% dimming marks unfocused segments, so the strip and the terminal say “not focused” the same way twenty pixels apart.
Not usedNo focus ring, no accent border, no underline, no seam lighting.

This is the only change that reaches terminal_element.rs. Everything else in this document is chrome.

Keyboard

Read from src/desktop_profile/keybindings.rs. One binding widens, one is reserved, four fill gaps. DesktopProfileError::DuplicateGlobalKey validates the set at construction after modifier normalisation, so a collision fails loudly rather than shadowing.

⌘PGo to anything — Workspaces, Tabs and Panes. WIDENED Today SearchWorkspaces. Same key, same palette, wider item source; the trailing chevron opens this. Safe to widen because ⌃1–⌃9 already activate Workspaces directly, so switching to a Workspace you know is one chord and ⌘P is free to be the fuzzy door to everything.
⇧⌘PCommand palette RESERVED Unshifted finds objects, shifted runs commands. The split developers already know.
⇧⌘[ / ⇧⌘]Previous / Next Tab MISSING Every macOS app with tabs has this pair. ⌃⇥ as the alternate.
⌘[ / ⌘]Previous / Next Pane MISSING Directional focus assumes you know the layout; cycling does not, and it is what you want when a Tab has two Panes.
⌃1 … ⌃9Activate Workspace 1–9
⌘1 … ⌘9Activate Tab 1–9
⌘NNew Workspace: This Mac or Remote over SSH
⌘T / ⇧⌘WNew Tab / Close Tab
⌘D / ⇧⌘DSplit Right / Split Down
⌘WClose Pane
⇧⌘⏎Zoom Pane — now the only expression of the zoom state, since the label is gone
⇧⌘H J K LFocus Pane by direction, with ⌥⌘ arrows as alternates
⌘B / ⇧⌘EToggle sidebar / Focus sidebar. The second plus type-to-filter replaces the search icon we deleted from the sidebar header.
⌘F / ⌘GFind in terminal, Pane-scoped. Unrelated to the two palettes, which is why neither of them may use a magnifier icon.

⇧⌘A was considered for the global search and dropped: the chevron and ⌘P were always the same idea and giving them separate keys is what made the whole thing feel confusing. ⌘K stays untouched, both because it is web vocabulary and because Terminal.app and iTerm2 use it to clear the scrollback.

Colour and theming

Two themes, not one. A terminal colour scheme is a 16-colour ANSI contract people already own and trade; chrome is a material system. Forcing both through one Zed document is why editor themes always look slightly wrong somewhere.

Terminal themeStays a Zed-compatible document. Vague Pro becomes one of these, not the theme.
Chrome themeRoles we own, derived rather than authored. Four inputs: base, accent, contrast, warmth.
Chosen independentlyChrome: Graphite, Terminal: Vague Pro. Ghostty, iTerm2 and Warp all work this way.
The accent appearsOn the lit Pane segment in the strip. That is the whole list.
It does not appearOn sidebar selection, the Workspace chip icon, focus rings, buttons or captions. Selection is a fill; focus is contrast.
AmberRemote and attention only. Globe icon, remote label, phase line, attention dot.
RedOnly where data is at risk. Not Close Pane, not Close Tab.

Derivation, not authoring

ChromeTheme { base, accent, contrast, warmth }

surface  = terminal.background                    // the Tab card IS the terminal
ground   = surface.desaturate(0.45).darken(0.25)
                  .clamp_saturation(0.12)         // a neon scheme cannot make neon chrome
control  = surface.lighten(0.05)
line     = surface.lighten(0.09)                  // the one divider colour

text_1   = contrast_ratio(surface, 11.5)          // never a fixed grey
text_2   = contrast_ratio(surface,  5.0)
text_3   = contrast_ratio(surface,  3.0)

Two things follow that a hand-authored palette cannot give. Text derived from contrast ratio against its own surface stays legible under any base, including a light one, so light mode is the same theme rather than a second one. And fixed elevation ratios mean no theme can invent the 8–12% jumps that make a UI read as a web page.

Window activation

The whole top row paints from the title_bar pair (#141415 active, #1c1c24 inactive), and tab_bar_background drops out of the top row entirely. The two are identical when active, so the focused state does not move a pixel and the inactive state becomes correct by construction rather than by two call sites agreeing. Chrome text and icons fall to text_muted in the same frame, which is what stops the lighter inactive band reading as highlighted. The active Tab cell follows too, or it becomes the one lit thing in a dimmed bar.

Cross-platform

VariesThe UI font: SF Pro, Segoe UI Variable, the desktop default. Type sizes, weights and the ramp do not change. Window controls, and the leading region that holds them. Scrollbar behaviour.
Never variesSurfaces, elevation, radii, spacing, control heights, accent, iconography and every layout decision here. If a Windows build needs different padding to look right, the padding was wrong on macOS too.
Not availableVibrancy. GPUI has no NSVisualEffectView, and faked translucency is the worst tell of all. Everything here is opaque and none of it wants blur.
12

Motion

Animate geometry. Never animate colour. Almost everything that reads as webby has this backwards.

0msHover fills, Pane focus changes, segment selection, caption contrast. Pointer feedback must be instant or it reads as lag rather than smoothness. This alone is most of the difference.
90msTab activation. The fill crossfades; nothing moves, resizes or slides.
120msCombo and menu open: opacity plus a 2px rise. No scale. Scaling a panel up from 0.95 is the most recognisable web animation there is.
140msA new Pane appearing: its width or height only, with the neighbour resizing in the same frame budget so the hairline looks like it slid.
180msSidebar toggle, on width. cubic-bezier(0.32, 0.72, 0, 1): fast start, long settle, no bounce.
200msZoom. The longest thing in the app, because it is the biggest change of state.
Reduced motionAll of it off. GPUI exposes the system setting; respecting it is not optional in a tool people use all day.

Delivery order

Ordered by how safely each piece lands alone. Each row is independently shippable.

1 · Activationtab_manager.rs stops discarding its Window; the whole top row paints from the title_bar pair. Depends on nothing. No visual change in the focused state.
2 · Theme rampFive values in the vague-pro-zed submodule, then the derivation module. The bundled_theme_matches_the_zed_adapter_for_every_color test keeps the fork and the adapter in step.
3 · Pane captionspane_host.rs: caption line replaces the header, one card per Tab with hairline splits, no index, up to four fading IconButtons, the · Zoomed string and its restore button deleted, degrade rules at count = 1.
4 · Focus treatmentterminal_element.rs: hollow cursor and reduced opacity for unfocused Panes. The only change reaching the renderer.
5 · Nav zone and sidebarworkspace_manager.rs: justified zone, two-line pill rows at 42px, no header, no panel fill, phase on the second line, sticky add row, counts only above one.
6 · Tab striptab_manager.rs: attached Tab cells, Pane segments with the label chain, the three-inline cap and overflow popover, click semantics, global ⋯ deleted.
7 · Menusmenu_theme.rs metrics, Pane and Tab menus split by scope, all hint footers removed, CommandPaletteHint retired.
8 · ComboBoxPlacement lifted out of menu.rs into a shared module, pinned fallback added to CommandPalette, then crates/spaceterm-ui/src/combo_box.rs, then the Workspace combo.
9 · Go to anything⌘P widens; needs cross-Workspace enumeration and a decision on live versus snapshot-on-open. Snapshot is the honest default: a list that reorders while you type is hostile. A feature, not a repaint.

16

Rejected, and why

Recorded so none of it gets re-proposed. Each of these was drawn and looked at.

Headerless PanesFocus by veil alone with no caption at all. Rejected: Panes need a grab surface for the drag feature, and the working directory is worth reading before you type.
Pane index badges1 · 2 · 3 anywhere. Rejected: nothing needs a number to be reachable once the strip carries the Panes in layout order.
Accent underline / full accent border for focusBoth drawn geometry laid over content. Rejected in favour of veil, hollow cursor and caption contrast.
Seam lighting for focusBrightening the hairlines around the focused Pane. Weakest of the four signals and the only one that re-adds geometry.
Floating Pane cards on a ground8px gutters, rounded cards, a darker canvas. Rejected: cards float, desktop apps meet. The gutter promises reordering that a fixed tiling never does, and it spends columns a tiling WM would never give away.
Coloured glyph badgesFilled rounded squares with > or @ inside, green for running, amber for remote. Rejected: reads as Slack presence badges.
Group capsule with chips insideA filled capsule per Tab holding filled Pane chips. Rejected: reads as NSSegmentedControl, which means “pick a mutually exclusive mode”. Also nested fills, and the deepest level of the model became the loudest thing in the bar.
Bare labels with hairlines onlyNo container at all, one filled label. Rejected: the strip stopped reading as a set of tabs and looked unanchored.
An inset pill for the focused segmentRejected twice, for the same reason both times: a fill inside a fill.
One-line sidebar rowsRejected: name and path compete for one line and both truncate. The row genuinely carries name, path or status, and a count.
Tab grouping in the sidebarDia's model, where sidebar and tab bar are two orientations of one list. Rejected: our sidebar is Workspaces and our strip is Tabs of the active Workspace. They are different lists, and a Workspace is an independent scope with an optional Pinned Directory.
A magnifier in the window chromeRejected: ⌘F already owns the magnifier for terminal find. A second one meaning “search Workspaces” would be a trap. Hence the chevron.
⇧⌘AA separate shortcut for the global search. Rejected: it and ⌘P were always the same idea.
Keyboard hint footers↑↓ Move ↵ Open esc Close. Rejected: never state a convention.
Showing Panes only when hiddenA rule where the strip listed Panes only for inactive Tabs and while zoomed. Logically clean, and overruled: Panes are always listed so any Pane is always one click away.

The last row is worth keeping in view. The strip does duplicate what the layout already shows, and that redundancy is a deliberate cost paid for always-available click targets. If the strip ever starts feeling noisy again, that is the first thing to reconsider — not its styling.
