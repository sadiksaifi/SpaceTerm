# Keep Workspace edits unavailable offline

When a server is disconnected, the SpaceTerm Client keeps navigation through retained Workspace and Tab state, personal rearrangement under [ADR 0042](0042-keep-tab-order-and-pane-layouts-specific-to-each-client.md), and Client Settings available. New Workspace edits, including Tab and Pane creation, Workspace renaming, and Kill Workspace, remain unavailable until the server reconnects. The client does not queue new Workspace edits for later execution, and offline navigation cannot start a shell.

Each paired route keeps a copy of the last Workspace Inventory its server confirmed, so this holds from launch until the route's first connection and after Disconnect, as it does after an interruption. The copy lives in the client's private storage for that route, beside its client views under [ADR 0042](0042-keep-tab-order-and-pane-layouts-specific-to-each-client.md). It holds Workspace, Tab and Pane identities, Workspace names, Split structure and each Pane's shell name, within the server's own bounds on each. It holds no title a program set, directory, Worktree, terminal content, command or live Session fact, and it grants no authority. The client writes it only when Workspaces, Tabs, Panes, Splits or names change. After Disconnect, a Pane reads the title a program set while this process still holds it, and otherwise its shell name. A route without a connection presents its copy with its Workspaces marked "Not connected", and each of its Panes says it is not connected and reaches no Terminal Session. When the route connects, its Workspaces, Tabs and this client's views of them stay in place and reconcile with the published inventory under [ADR 0036](0036-publish-workspace-changes-to-connected-clients.md). Two saved routes can reach one server. A server with a connected route presents no copy, and a server with no connected route presents one copy, the one with the newest revision. Removing or unpairing the route removes its copy.

Detach Workspace removes the local attachment and invalidates local control-resumption rights immediately, even while the server is unreachable. Server-side control release completes when the server becomes reachable and targets only the original control grants; it cannot release another client's takeover or a grant acquired later. Self-Unpair retains its immediate local removal and durable revocation workflow under [ADR 0038](0038-unpair-devices-without-blocking-local-connection-removal.md).

An operation submitted before the interruption may already have committed. Reconnection resolves that operation's outcome using its original identity under [ADR 0037](0037-resolve-shared-mutations-at-the-server.md), so a lost acknowledgement does not become a false failure or a duplicate edit. Terminal presentation and input handling follow [ADR 0045](0045-freeze-terminal-screens-while-reconnecting.md).
