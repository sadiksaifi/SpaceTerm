# Scope Settings to the client or selected server

Client Settings remain specific to the client device, while Server Settings belong to one SpaceTerm Server. Servers and Git share one searchable borderless server picker in their page headers. It lists the account-local server first, saved SSH servers next and paired servers last, and offers Add Server. No other Settings page presents it. Selection is shared between those two pages and retained across launches outside the Settings Document. Removing the selected server falls back to the account-local server.

Servers presents one selected-server card, Network Access for account-local and SSH routes, and All Servers. The selected-server card owns status, version, automatic-start policy and Terminal Sessions. Destructive management actions live in its menu and confirmed sheets. Every operation names its server. Paired connections carry SpaceTerm authority and no native service authority. Add Server is one sheet for SSH and Invitation Link enrollment, reachable from the picker, All Servers, Settings Search, application menu, command palette and operating-system invitation delivery.

End All Sessions follows [ADR 0048](0048-end-all-sessions-from-the-selected-servers-settings.md).

Interface, Font, Themes, Keybindings, clipboard preferences, Git presentation preferences, and client update preferences remain client-owned. Clipboard preferences govern that client's clipboard under [ADR 0013](0013-order-terminal-clipboard-access-by-session-focus.md) and the Pane control rules in [ADR 0022](0022-give-one-client-control-of-each-pane.md). GitHub CLI authentication and Pull Request lookups retain the client-local ownership in [ADR 0018](0018-read-repository-status-by-running-git-and-the-github-cli.md).

Git discovery and execution use the owning server's tools and filesystem. Git separates client-owned Repository Status and Pull Requests from "Git on <server>". New Worktree Location belongs in that server section. Its template expands and validates in that server's filesystem context, including effective write and search permission on the nearest existing folder. The field reports validation errors as the person types. A concurrent edit reloads the authoritative value and explains the change. Settings edits it through the selected server's existing connection, and only while that server is connected. Legacy Worktree Location seeds a new local server once and never overwrites an existing server. System Permissions remain operating-system capabilities on the machine where the terminal program uses the protected resource, following [ADR 0014](0014-guide-permission-setup-on-system-settings.md); a client's permission setup cannot grant another machine's permissions.

Status shown for a connected or requested route comes from the worker that owns that connection intent under [ADR 0045](0045-freeze-terminal-screens-while-reconnecting.md). Selecting, rendering, searching or opening a Settings page opens no remote connection and starts no discovery. An inactive server presents its timestamped last-known facts with unavailable rows dimmed and a footnote explaining how to connect. Only an already connected server answers Server Settings reads over its existing connection. Check Status requests one fresh observation of an inactive saved connection. It may obtain SSH interaction because the person asked, and it connects, starts and installs nothing. It leaves connection intent unchanged, except that finding a deliberately stopped server ends any reconnect intent, as Stop does.

The account-local server needs no pairing and offers no removal. Removing a saved SSH connection is immediate. It removes the connection's presentation and ordinary reconnect intent, and it leaves SSH account access, the server, its Terminal Sessions and restricted pending originals in place under [ADR 0029](0029-pair-clients-automatically-during-ssh-bootstrap.md). A submitted original that is still unresolved, or whose validated result is waiting to be acknowledged, stays presented in the Servers section after its connection is removed, offering only its resolution and that acknowledgement. Presenting it recreates neither the removed connection nor its reconnect intent, and a connection saved again under the same destination inherits neither that original nor its late results. Direct-network Unpair Device follows [ADR 0038](0038-unpair-devices-without-blocking-local-connection-removal.md).

Advanced import, export, and reset operate on Client Settings and installed Terminal Themes in the Settings Document, whose schema stays 7. Saved connections and their retained intent, server identity, device credentials and authorization, pending operations and unpair requests, Workspace Attachments, Client View State, server-owned Workspace organization, Server Settings, and deliberate Stop Server state remain outside the Settings Document, so preference transfer or reset cannot change those lifecycles. Server update restarts retain the confirmation requirement in [ADR 0034](0034-confirm-server-update-restarts-and-explain-incompatibility.md).
