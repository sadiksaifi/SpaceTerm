# Order terminal clipboard access by Terminal Session focus

Clipboard Authority belongs to the originating Pane's Terminal Input Focus, and reads need explicit permission, because terminal output can come from local or remote programs. Clipboard requests use a bounded asynchronous channel because blocking the worker on a UI reply would deadlock a synchronous Selection query.

A program that copies its own selection writes the clipboard of the computer it runs on, which is not the presenting client's when SpaceTerm Core is on another Machine. [The shell launch policy](../../src/platform/shell_launch.rs) therefore sets `PI_CLIPBOARD_OSC52=1` in every Terminal Session, so pi also sends each copy as OSC 52 under this authority. Codex offers no program-neutral marker, so a Terminal Session that a paired device starts also carries Herdr's `HERDR_ENV=1`, and a program there that checks it believes it runs inside Herdr. Codex writes HTML beside plain text to the native clipboard, and a plain-text OSC 52 write would replace it, so a Terminal Session started on SpaceTerm Core's own computer carries no `HERDR_ENV`. The marker follows the client that started the shell: a Session later presented from the other computer keeps it or lacks it. SpaceTerm Core counts every paired connection as another computer's, so a desktop paired with the Core on its own computer starts shells with the marker.
