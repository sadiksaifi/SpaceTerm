# Administer servers over the service lane

Status, Stop, Restart and Update use a service lane on the authenticated account-local or paired connection. [ADR 0027](0027-trust-paired-clients-equally.md) owns authority and machine-only actions. `server unpair` accepts only the local route, including when the target is another Paired Device. [CLI route validation](../../crates/spaceterm-cli/src/connection/route.rs) rejects a remote route before credential or transport access.

The lane uses bounded length-prefixed JSON through the admission preamble, independently of the work protocol major. An incompatible work client can therefore update a server and settle the same operation after reconnecting. This is one lane on the existing transport. [ADR 0035](0035-negotiate-one-protocol-major.md) owns its version policy. [The lane contract](../../crates/spaceterm-server/src/service/lane.rs) includes the admitting `boot` in `Accepted` and the candidate's `to_major` in update effects. Clients use those fields to check replacement and warn when work commands will need a matching client.

A lane Status or Check request reads facts without activation recovery. The local CLI update entry point settles activation before opening the lane, including for `--check`. Unreachability does not establish that a server is stopped; any last-known connection time is explicitly dated under [ADR 0058](0058-derive-agent-identities-at-admission.md). Update delivery uses a signed target feed fetched by the server or a paired upload. The server verifies the candidate under [ADR 0040](0040-keep-one-server-runtime-version-active.md).

The server feeds are `spaceterm-darwin-arm64.json` and `spaceterm-linux-x86_64.json`. Each feed and archive has a raw 64-byte detached Ed25519 signature. The feed's archive signature is base64 inside JSON. [Release signing](../../mise-tasks/lib/spaceterm_tasks/release.py) writes the schema-1 identity, target, version, publication time and archive description; [feed verification](../../crates/spaceterm-server/src/service/feed.rs) authenticates that document before downloading its named archive.

A running server's preview binds an actor, action, server, boot, service state or activation approval, and exact affected Terminal Session set. [The lane observation digest](../../crates/spaceterm-server/src/service/lane.rs) hashes those service observations and the sorted Session IDs when the service is running. Update and Return bind the activation approval's confirmation digest; Stop and Restart bind the retained service state. The server retains at most 16 random `c1-` tokens, each redeemable once by its actor and action within ten minutes. Issuing past capacity drops the oldest token. A server restart loses the registry. [The token registry](../../crates/spaceterm-server/src/service/tokens.rs) refuses unknown, spent, expired or mismatched tokens as `changed`.

Offline Update on the server's own machine and Unpair use `c1-` digests of their current observations instead of a server-held token registry. [Offline Update](../../crates/spaceterm-cli/src/server/update.rs) uses the activation or return approval digest. [Unpair](../../crates/spaceterm-cli/src/server/unpair.rs) hashes the server ID, exact pairing ID and device public key. Each command recomputes its digest before acting and reports `changed` on a mismatch. These tokens remain valid while their bound observations are unchanged.

Admission revalidates the preview and durably records the operation while holding the pane-service lock. It sets the membership fence under that same lock. While any admitted service operation remains unsettled, [the host request path](../../crates/spaceterm-server/src/host.rs) refuses every `Claim` with `ServiceBusy`, exposed as `service_busy`. This includes reattaching to an already running Terminal Session. Organization edits that start no Terminal Session remain available. This is the v1 membership policy. Repeating the operation ID resolves that record and never repeats the action.

The approved runtime launches a transient helper outside the server service's process tree: a collected systemd user unit on Linux, or `posix_spawn` with `POSIX_SPAWN_SETSID` on macOS. It inherits no server sockets or lock descriptors. [The helper](../../crates/spaceterm-server/src/service/helper.rs) holds `service-helper.lock` for its whole run, reads only its admitted record and runs the same native operation as a local caller under the service lock. A free helper lock proves that no helper is acting when [ledger settlement](../../crates/spaceterm-server/src/service/operations.rs) examines an interrupted operation. No permanent helper is installed.

The durable ledger records admission, launch, execution and the terminal outcome. Startup recovery marks an admitted operation that never launched as not performed. Interrupted Update resolves through activation recovery; an unprovable Stop or Restart stays unresolved. A changed boot alone is not a generic success receipt. Unacknowledged records remain until the same actor acknowledges them or its pairing is revoked. The ledger refuses new admissions at capacity instead of expiring records by age.

Restart and Update reconnect over the lane and resolve their receipt before reporting completion. Stop returns exit 7 with shutdown observed because losing the connection cannot prove native cleanup. A later connection after local Start settles that receipt. [ADR 0034](0034-confirm-server-update-restarts-and-explain-incompatibility.md) owns activation confirmation, cross-major candidates and return to a previous runtime.
