# Own status controls in the desktop client

The desktop SpaceTerm Client owns its windows and native status item in one process. The menu bar/status area is part of that client, with no separately installed status application or helper registration. The installed Preflight and Release SpaceTerm Server remains independently supervised and headless under [ADR 0030](0030-start-servers-at-boot-independently-of-clients.md).

Command-Q and equivalent application Quit requests, including Quit from the application menu and macOS Dock, close every client window without a quit warning while the status item is available. The same client stays in the menu bar or status area and leaves the Dock. Opening SpaceTerm restores its windowed presentation. A window with busy Panes owned by the desktop still requires its existing Close Window confirmation.

Every user-requested exit requires a quit warning, even with no Terminal Sessions or windows. This includes Quit from the status item, application Quit without an available status item, closing the last Linux window without a status item, and losing the status area while no window is open. A windowless client presents the warning in a temporary window that creates no Workspace. Cancel restores windowed presentation when no status item or other window remains, so cancelling never leaves the client unreachable. Operating-system logout, restart, and shutdown proceed without a warning.

The warning names the build. For installed builds, it says that the client leaves the menu bar or Linux status area while its Terminal Sessions keep running. Quit is the default answer and Cancel keeps the client running. Stop, Restart, Update, Uninstall Server, and End All Sessions remain distinct confirmed operations. This replaces the application Quit chooser required by [issue #624](https://github.com/sadiksaifi/SpaceTerm/issues/624), following [issue #641](https://github.com/sadiksaifi/SpaceTerm/issues/641).

An installed client crash may remove the status item but leaves server-owned work running. The supported service-control fallback remains usable without the client or a status-area host. A later desktop installation reuses an existing headless installation under [ADR 0033](0033-reuse-one-server-across-headless-and-desktop-installations.md). The future general CLI in [issue #596](https://github.com/sadiksaifi/SpaceTerm/issues/596) records intent only and does not expand this control surface.

For source Development, the development command owns the complete run under [ADR 0030](0030-start-servers-at-boot-independently-of-clients.md). Closing windows keeps that run available in the status area. Every actual client exit or ending the command ends its foreground Server and Terminal Sessions. When the run has Terminal Sessions, the quit warning explains this and makes Quit destructive. Its count comes from the run's authenticated Workspace Inventory, including Terminal Sessions without open windows. The client reads that inventory again after saving Settings and waiting for admitted operations. A restarted server or newly affected Terminal Sessions require fresh confirmation. An unavailable reading prevents exit rather than treating unobserved work as zero.
