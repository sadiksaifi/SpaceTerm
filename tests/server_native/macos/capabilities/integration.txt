Capability fixture integration contract

This is evidence-only code. It grants no startup, installation, credential-release,
or GUI authority. The ordinary gates build the unsigned effect executable and run
injected peers, process-identity reads and throwaway unprivileged children. They
never run sudo, change privacy settings, write the general clipboard, or open a
Keychain. No GUI/daemon matrix result is credited by those gates.

Assembly and admission

Use build_fixture(destination, environment=...) in capability_tests.py. It embeds
ProbeInfo.plist but neither signs nor executes the effect executable. The evidence
assembler uses the existing signing helper and the authenticated publisher. Never
elevate an account-writable staging executable.

The installed path, certificate and identifiers are in capability_internal.h.
Workers require protected non-symlink code ancestry, the pinned signature,
hardened runtime and empty entitlements. Those checks are necessary preflight,
not fresh-publication or historical write-exclusion authority.

The same executable runs in both interactive PTYs. It observes the nearest signed
desktop/companion or server ancestor, rather than trusting an asserted context.
The independent libSystem responsibility observer binds the actual effect and
responsible-process identities and audit session before and after the effect.
Code requirements classify the responsible actor; failed observation stays
Unknown. Ancestry alone never establishes responsible-process attribution.

Invocation and observations

The standalone entry is --run <case-code> <context-code> <absolute-monotonic-ns>
<targets-fd>. The descriptor carries exactly one st_capability_targets followed by
EOF. Schema 2 is 4,144 bytes: four u32 fields (schema, companion PID,
window ID, controller PID), sixteen run-ID bytes, sixteen fresh target-nonce
bytes, and the 4,096-byte selected-volume field. Bind both nonzero IDs, optional
companion PID/window and controller PID, and explicitly selected volume directory. Targets are nonauthorizing facts. Paths never enter
arguments or output. A controller compiled against another identifier cannot
replace the signed probe as a worker parent.

The result is exactly one 32-byte big-endian capability observation. Translate it
through the shared evidence schema with actual run, sequence, host, revision,
artifact and proof metadata. A preflight, successful utility exit, missing record
or synthetic test output cannot become native Passed. Denial, cancellation,
unavailable prerequisites and unresolved cleanup remain distinct.

Ordinary effects have one five-second absolute deadline. Only the explicitly
requested sudo case allows sixty seconds. Partial output and EINTR never reset
it. Worker re-exec strips unrelated environment and suppresses raw stderr. PATH
and locale comparison runs in the original probe, not a worker. SSH imports only
its socket selector; GPG uses native default-location discovery. The controller
must also bound synchronous native preflight and retain unresolved resources when
interruption loses an observation. Darwin writes use descriptor-local SIGPIPE
suppression, without changing another thread's masks or pending signals.

Synthetic targets

Authenticate the companion identifier from capability_internal.h. Its capture
window title is "SpaceTerm Evidence Targets". Bind the actual PID
and WindowServer ID. Screen capture retains dimensions, never pixels. Microphone
callbacks discard samples. Neither case requests a privacy grant automatically.

The Accessibility target identifier is "spaceterm-evidence-accessibility-target".
Set AXValue to "spaceterm-evidence-<target-nonce-hex>". The target consumes the
marker into its ledger and deliberately returns an empty AXValue, so read-back
equality cannot prove the effect. Require the accepted nonce-bound receipt.
No unrelated application receives an Accessibility operation.

The URL is spaceterm-development-native-evidence://receipt?run=<run>&nonce=<nonce>.
URL delivery uses Launch Services, not Automation. Apple Event class 'STev',
event 'rcpt', carries run and nonce in 'Srun' and 'Snon'/typeUTF8Text. An accepted
reply carries "accepted" in its direct object and echoes both IDs. Apple Events
disallow interaction. The URL, marker and event constants come from the retained
companion_receipts.h, not a second target application or protocol.

The existing companion ledger must be bound and armed with a fresh target nonce
before each effect. For URL and Accessibility, E4's fixed signed evidence client
consumes that companion's accepted receipt and exposes a metadata-only socket at
/private/tmp/spaceterm-native-520-<run>.<case-code>.receipt.sock, with collision
refusal and scoped cleanup. No receipt is synthesized from dispatch or preflight.
The native consumer authenticates the separate controller PID, start identity,
UID and .native-evidence.client code requirement before and after the exchange.
Request and accepted reply are exactly 44 bytes: ASCII SCTR, u32 big-endian version
1, u32 big-endian case 5 or 7, sixteen run-ID bytes and sixteen target-nonce bytes,
followed by EOF. The client echoes only after observing the matching accepted
companion receipt. This is nonsecret effect metadata, not the removed private
PATH/locale channel. Missing targets, client or receipt remain unavailable. The
real client composition is E4 work; injected URL/Automation ports and the actual
retained ledger are tested here, never a success-shaped native fallback.

Before the owner-requested folder tests, prepare only the run-bound markers in
the native Desktop, Documents and Downloads directories and on the explicitly
selected volume. Each marker contains exactly the sixteen run-ID bytes. Keep a
scoped inventory and remove only those created objects. The worker opens the
files itself, so pre-opened descriptors cannot bypass the tested folder access.

The bounded clipboard peer checks the synthetic nonce marker and unchanged
changeCount. It never clears, writes, or restores the clipboard. Injected peers
exercise preservation of other formats and intervening owner changes.

Native general-clipboard read is Unavailable on the current Darwin profile.
AppKit materializes NSData before exposing its length. RLIMIT_AS blocks mmap but
not Mach out-of-line receive: an unprivileged 64-MiB receive crossed a 16-MiB cap.
The native text adapter therefore refuses before dataForType. This is a zero-
acquisition policy, not proof of successful clipboard read. No clipboard content
is acquired or logged, and no runtime switch bypasses the refusal. An explicit
owner Copy or pbcopy action can supply separate write evidence.

Owner regression general_clipboard_acquisition_refuses_oversized_and_preserves_formats:
prepare explicitly synthetic text, HTML and image formats; replace the text with
an oversized synthetic selection immediately before case 6 in each context;
require Unavailable with Unobserved effect, bounded worker memory and all prepared
formats and the newer selection unchanged. Compare only the owner's known
synthetic data outside the probe. Do not translate the refusal into Passed read
evidence. This owner-authorized general-pasteboard sequence remains unrun.

The login-Keychain case opens only the account's fixed login.keychain-db with
interaction disabled. It refuses collisions, creates one run-bound random
synthetic value, verifies its exact round trip, wipes owned bytes, deletes the
exact new item, and checks absence. Worker loss after enrollment is cleanup
unresolved. No System Keychain or real account credential is selected.

SSH sends an unsupported synthetic extension, never a key enumeration or signing
request. GPG reads only an Assuan greeting and GETINFO version, discarding response
lines. Modern GPG discovery uses the native account home and default .gnupg socket,
not GPG_AGENT_INFO, GNUPGHOME, arbitrary gpgconf, or the complete GUI environment.
The account GeneratedUID and active GUI-session incarnation are checked before
connection and at completion. The Rust counterpart also discovers the default
Linux runtime socket and rejects a replaced socket, session, account or expired
lease. It never starts an agent or changes agent configuration.

Touch ID fixed-command cleanup

The only commands are /usr/bin/sudo -k followed by /usr/bin/sudo /usr/bin/true.
Each forked root blocks on a start pipe until its uniqueid has been retained.
Each command has its own session/group, fresh PTY and fixed environment. After
setsid, the child acquires that fresh slave with TIOCSCTTY and makes its own group
foreground before exec. Duplicating the outer worker's tty does not establish a
controlling terminal for a new session.

The worker forwards opaque terminal bytes between the owner tty and the new PTY.
Only the inner terminal's line discipline and sudo own the password conversation.
The forwarding buffer is bounded and wiped after each transfer. There is no
password parser, response object, capture, logging, AskPass, -S or -E. The outer
TTY temporarily uses raw forwarding modes. Normal retirement restores its modes;
the owning probe also restores them after abrupt worker loss, but never overwrites
a newer foreground-group change or unrelated terminal mode changes. The native
unprivileged regression runs this exact pre-exec setup and verifies /dev/tty,
foreground ownership, canonical input, Ctrl-C delivery and mode restoration.

After exact root reaping, a trivial gated sentinel supplies the upper uniqueid.
The native scan reads p_uniqueid and p_puniqueid for all live processes, masks the
exec-shadow bit and retains historical fork-parent links. It signals only proven
members after rechecking uniqueid and pidversion. proc_signal_with_audittoken
also checks pidversion in the kernel, closing the read/signal replacement race.
Bounded fixed-point rescans require zero members and zero unknown ancestry chains
inside the root/sentinel window. EPERM or surviving/unresolvable members produce
CleanupUnresolved. Direct-child exit and process-group emptiness never substitute.
No NOTE_TRACK or general descendant containment is used.

The outer signed worker has its own retained uniqueid scope for interruption
before inner retirement. It restores the owning PTY's foreground group only if
no newer foreground change occurred. Zero sudo exit means CompletedUnattributed:
it does not prove Touch ID rather than password. The owner and native observation
must identify the authentication method. Actual sudo and its cross-UID process
tree remain owner-run evidence, not credit from the unprivileged PID-1 read test.

Local environment comparison

Case 13 verifies the actual parent account /bin/zsh or /bin/bash, start identity
and controlling PTY. The originating shell normalizes its own login/interactive
mode locally. Never query parent KERN_PROCARGS2: it can return initial private
environment bytes even after the shell unsets them.

The shell supplies exactly two ASCII bits followed by EOF on a mode descriptor.
The first bit means login, the second interactive. The shell emits 00 for command
or script execution. Only 11 permits the comparison. These public facts grant no
authority and need no private-value sender channel. For zsh, compute them with
[[ -o login && -o interactive && -z $ZSH_EXECUTION_STRING && -z $ZSH_SCRIPT ]].
For bash, require shopt -q login_shell, an i in $-, an unset BASH_EXECUTION_STRING,
and no script in BASH_SOURCE. Run this producer from the actual interactive PTY,
not a shell invoked with -c or controlled startup replacements. Do not export
private mode-comparison inputs in an environment variable.

Case 13 invocation adds <mode-fd> after <targets-fd>. Other cases retain their
original argument count. A pipe's mode descriptor can be stdin; it must differ
from the target descriptor. The environment-only entry is now --environment
<context-code> <mode-fd>. E4 must supply this public producer in both contexts.
The actual-boundary regression starts a shell with a synthetic initial variable,
unsets it before the probe, and rejects any native parent procargs acquisition.

--environment <context-code> <mode-fd> emits exactly twenty big-endian bytes: schema 2,
observed context, reference 1, PATH difference, locale difference. Reference 1 is
PATH /usr/bin:/bin:/usr/sbin:/sbin, LANG C, and absent LC_* values. Each process
compares private values locally against that public baseline. PATH classifications
are Equal, PresenceChanged, ComponentsChanged and OrderChanged; locale
classifications are Equal, PresenceChanged and ValuesChanged. Presence change
wins over a simultaneous value change. No value or digest crosses a process
boundary. The private-value codec, refusing channel and pair entries were removed.

Rust LocalEnvironmentComparison recognizes this record. Equal means equal to the
public baseline, never exact GUI-versus-daemon equality. Matching normalized
facts from two contexts cannot establish their private environments are equal.
Keep the two contexts separate in collection. The shared JSONL consumer must
retain the local reference and context rather than relabel these as exact pairwise
equality. Controlled shell-fixture startup order remains a separate experiment,
not evidence of the account's private configuration or complete shell cleanup.

Native session adapters

SystemGuiSessionObserver composes the account owner's NativeAccountProvider with
SystemNativeGuiSessionPeer. macOS uses console/audit-session state, boot identity
and the loginwindow uniqueid. Linux uses active graphical logind session state,
a retained session record and leader pidfd. Repeated observation invalidates ended
or replacement sessions. A purpose-bound lease also expires after at most thirty
seconds and rejects another broker or account.

SystemSessionConnector provides only default GPG and account user-bus/portal
connections. Its closure receives SessionConnection, not a bare UnixStream.
Every nonblocking read/write syscall revalidates the account, session, purpose,
endpoint identity and original lease expiry. Poll waits recompute the remaining
lease time and last at most ten milliseconds, so partial output cannot renew a
lease and logout is noticed during a silent read. Completion revalidates again.
The real-clock regressions cover slow drip, expiry before write and logout during
read, and verify that no later request reaches the peer. It never imports DISPLAY,
WAYLAND_DISPLAY or the whole graphical environment. No speculative broker or GUI dependency is
added to the headless host. Use the ordinary desktop/daemon composition owners to
inject these adapters. Actual logout, portal GUI effects and the signed 13-case
matrix remain unrun until the owner-directed sequence.
