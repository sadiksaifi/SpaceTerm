# Use SpaceTerm Protocol over every client connection

SpaceTerm Protocol carries operations and authoritative server state over account-local IPC and paired QUIC. [ADR 0027](0027-trust-paired-clients-equally.md) defines admission authority. Remote connections never fall back to SSH.

Network access requires deliberate exposure authorization and retains one explicit bind policy and server identity across restarts. Turning access off retains the configured listener for the next deliberate enable. A change binds or widens its new listener before it saves the policy or retires the current listener, so an address the server can't listen at fails as `address_unavailable` and changes nothing. Only a narrowing from every interface to one address waits for the current listener to retire, because no other socket can hold an address that listener covers. Configuration can change while exposure is off. The person supplies QUIC reachability through their network, VPN or tailnet. SpaceTerm operates no relay; SSH aliases and ProxyJump establish no QUIC route. Client endpoints accept DNS names and IP addresses independently of the server's bind address. DNS resolves on each connection; server certificate and proof-key pins remain the authority.

An Invitation Link contains the reachable address, pinned TLS certificate, public proof key and a strong one-use secret. The server enforces its five-minute expiry. Clients use the issued lifetime for monotonic waiting and presentation; differences between client and server wall clocks cannot reject a claim. The claimant verifies the pinned server before submitting a signed claim. Both proofs bind the server and exact claim; both screens display the same authenticated six-digit Comparison Code. An account-local client approves that exact claim after comparison.

Invite Device presents the link and QR code. Add Server waits for explicit Join. Operating-system `spaceterm://pair/…` delivery opens that same Settings journey on launch or in the running client. Invitations remain transient and never enter retained state, diagnostics or child commands.

Enrollment binds a device credential and pairing to one Client Identity before terminal admission. [ADR 0004](0004-resolve-application-directories-by-xdg-convention.md) owns native credential storage and CLI behavior when the store is unavailable. A new pairing cannot claim another pairing's views or Pane control by supplying its identity. Cancellation and lost replies follow [ADR 0038](0038-unpair-devices-without-blocking-local-connection-removal.md).

A client may present an Agent Name at admission. The server derives a distinct Client Identity from the connection's base Client Identity and that name. An agent's views, Pane control and operations stay separate while sharing the connection's authority. An Agent Name cannot reach another pairing's identity. Before admitting an agent, the server durably records its name in that pairing. Each pairing keeps at most 64 names, ordered from least to most recently admitted. Reusing a recorded name moves it to the most recent position. A new name past the limit evicts the least recently admitted name that has no live connection and holds no unacknowledged edit outcome or run receipt. The server releases the evicted identity's Pane control grants. It releases nothing else. A returning agent waits for that release before it is admitted. If that wait outlasts the admission deadline, admission fails with `capacity`. If the host stops during that wait, admission fails with `disabled`. If no name qualifies, admission fails with `capacity`. Revocation reaches only recorded names, so a name that still holds an outcome or receipt is never evicted. Revoking the pairing retires its base identity and every recorded agent identity, releases their Pane control and closes their connections and observations. [The direct host](../../crates/spaceterm-server/src/direct/host.rs) owns admission and retirement; [direct storage](../../crates/spaceterm-server/src/direct/storage.rs) owns the bound. The command-line client and the desktop never share a Client Identity. [ADR 0058](0058-derive-agent-identities-at-admission.md) owns agent identity derivation and CLI state.

[ADR 0050](0050-push-terminal-presentation-over-one-multiplexed-connection.md) owns the pushed, multiplexed work exchange. [ADR 0057](0057-administer-servers-over-the-service-lane.md) owns the admission-time service lane.
