# Define the CLI output contract and scope model

The CLI serves people and automation through the same commands. Text is the default. `--json` emits the versioned `spaceterm.cli.v1` envelope and requires noninteractive behavior. Only `connection add --json` streams NDJSON: its Comparison Code event precedes the final envelope. `contract.rs` in `crates/spaceterm-cli/src/` owns the envelope, per-command data, fixed errors, warnings and exit mappings. Fields may be added within a schema version; removing, renaming or retyping one replaces that version outright.

Errors and warnings contain fixed classifications and bounded typed metadata. Labels, directories, candidate descriptions and captured terminal output are requested operational data on stdout, including when a command fails. They never enter stderr errors, warnings or diagnostics. Exit codes distinguish success (0), failure (1), usage (2), action required (3), target (4), unavailable (5), deadline (6), unconfirmed (7), interruption (130) and broken stdout pipe (141). Usage validation happens before effects. Exit 7 reports an unconfirmed dispatched outcome and takes precedence over interruption or failure. A confirmed running command that reaches its deadline reports timeout without cancelling the command. A broken stdout pipe exits silently.

Targeting selects one server first: `--server`, then `SPACETERM_SERVER`, then `local`. Child selectors never search other servers. Explicit selectors resolve against one Workspace Inventory and repository snapshot; their memberships must agree. Compatible current Terminal Session context fills a missing level only when nothing explicit at or below that level supplies it. Single candidates fill the rest before command-specific creation defaults. Ambiguity stops the operation and returns candidates with handles to copy. Worktrees have path identity; other work objects and saved routes support IDs. Every resolved level reports where its value came from.

Destructive commands require an explicit ID, exact handle or validated current context at the acted-on level. A singleton or substring cannot choose that target. Confirmation binds the exact action and its affected work; changed observations require a new preview. Local connection-store commands reject a remote server selector before effects. Remote paths are absolute or begin with a literal `~/` expanded by the owning server. Local relative paths use the CLI's working directory. Creation uses the same server directory policy and shared client operations as the desktop. A Tab defaults to the current source Pane in its Workspace, otherwise the Root Tab's Root Pane; a split defaults to the current Pane in its Tab, otherwise its Root Pane.

`pane run` admits one verbatim shell command against an exact Terminal Session, control lease, owner-marked prompt and empty input line. Bracketed paste inserts it without argv joining. Line Mode alone cannot establish a shell prompt. A server receipt correlates command start and finish; a missing exit status remains unconfirmed. Resolving a lost reply never resends terminal input. Captured output is bounded terminal presentation and reports gaps or coalescing. `pane send` reports delivery only when the server acknowledges that its input serial reached the PTY. Run receipts and Original Operation journals remain separate under [ADR 0058](0058-derive-agent-identities-at-admission.md).
