# Carry paired connections over QUIC

Paired connections run over QUIC, the only paired transport. WSS, its TCP listener and its code are deleted, with no fallback. On a lossy network the tail of a paired keystroke came from TCP: Linux recovers a lost lone packet only after its 200 ms minimum retransmission timeout, and every later frame waits behind it on the one byte stream. QUIC recovers after one probe timeout derived from the measured round trip, and a lost packet stalls only its own stream. At 2% loss and 25 ms added delay on the server's side, the noq-proto carrier this decision describes, measured at commit d3a806dc against WSS in the same session with n = 300 per cell, cut keystroke-to-echo p99 from 257 ms to 82 ms, the p99 of a pushed page of output from 283 ms to 83 ms, and the p99 of a 200-row Scrollback page from 290 ms to 114 ms. On a clean wired LAN a keystroke costs the same on both: 2.0 ms over WSS and 2.1 ms over QUIC at p50, each n = 300.

SpaceTerm drives noq-proto, the QUIC state machine that n0's iroh runs on, from each connection's own I/O thread. noq-proto does no I/O and needs no runtime, so a frame crosses no extra thread on the client, and the server's one UDP socket is read by a listener thread that hands each datagram to its connection's thread. iroh itself was measured and rejected: its relay client, DNS resolver and network monitor are not optional, link Apple's Security, SystemConfiguration and CoreFoundation frameworks, which the macOS server cannot link when it is cross-compiled on Linux, and doubled the server binary. Its runtime thread added about 0.9 ms per keystroke on the LAN. noq-proto and noq-udp add 26 crates to the server and remove 7, add about 1 MB, and link no framework.

Trust is unchanged under [ADR 0027](0027-trust-paired-clients-equally.md) and [ADR 0028](0028-use-spaceterm-protocol-over-every-client-connection.md). TLS 1.3 inside QUIC presents the same pinned server certificate, and the pairing exchange then verifies the server's proof key and the device's proof. The client also presents a self-signed certificate of its device key, and the server requires that key to be the enrolled key of the device that proves itself, so a proof cannot travel on another device's connection. Endpoints are `quic://HOST:PORT`; the server listens on UDP at its exposure's address and port, 9231 by default.

Frames of one priority level arrive in the order they were offered. L0 is the bidirectional stream the server opens for pairing and admission; the server writes L1 and L2 on unidirectional streams of their own, so bulk transfers and lost frame packets never hold up L0. Each level has its own flow-control backlog, so a bulk transfer that waits for credit never holds back a reply or a ping. The client writes every level on L0, so a cancellation or an edit acknowledgement never overtakes its request. On close the server finishes all three streams, and the client holds the server's goodbye until L1 and L2 end, so a goodbye never overtakes frames in flight. Across server levels there is no other order, as on WSS's priority queue.

Before admission, an unauthenticated peer can make the server hold little. An Initial packet from an address not yet proven gets a stateless retry, which costs one round trip on a new connection, so spoofed sources hold no state or slot. Until admission each connection may buffer 64 KiB, and the datagrams waiting for one connection's thread are bounded. Each stream holds at most one largest frame unread. A closed server connection drains on the listener's thread for three probe timeouts, at least 1 second and at most 3, and sends its close again, at most 8 times, when the peer's packets show the close was lost. A refusal whose close was lost therefore still reads as a refusal, not as a stateless reset. At most 64 connections drain at once; past that a closed connection is forgotten at once.

Terminal traffic is a few packets at a time, so the configuration favors recovery over economy. Each side asks the other to acknowledge every packet at once, which keeps acknowledgement delay out of the probe timeout. The congestion window never falls below ten packets, the usual initial window, because Cubic grows only while its window limits sending, so random loss alone would ratchet it down to two packets and a screen of output would wait a round trip. BBR paced this traffic far too slowly. Keepalives every 10 seconds hold the UDP flow open through routers.

A client whose network changes moves to a new UDP socket, opens a new QUIC path from it with the multipath extension, and abandons the old path. Both ends start the new path's round-trip estimate and congestion window afresh, and the server validates the new path without a second handshake or admission, so the client keeps Pane control. Plain RFC 9000 migration keeps the old path's estimate when only the port changes, as behind one address of a tailnet or NAT, and the server gives up validating a slower new path after three of the old path's probe timeouts. The path then stays unvalidated, the server may send only three times what it receives, and replies stall until the client moves again. Through a test relay that moved a client from loopback to a 40 ms round trip with a request lost on the old path, replies after the move waited 7.6 s under migration and at most 145 ms with a new path. Each connection holds at most two paths. Data lost on the abandoned path is sent again once that path drains, three of its probe timeouts after each end learns it was abandoned; the server first tells the client on the abandoned path, so the two drains run one after the other. On a wired network that is milliseconds. Three things trigger the move: a send that fails because the local address left, a ping left unanswered for 2.5 seconds, well before the 15-second rule ends the connection, and a change in the local address the system would use to reach the server. The third brings a client back to Ethernet when its cable returns while Wi-Fi still works, because then no send fails and every ping is answered. The client asks the routing table for that address by connecting an unbound UDP socket, which sends nothing. It asks once per 5-second ping interval and after each route-change signal: a `PF_ROUTE` socket on macOS and a netlink socket on Linux, opened without any framework. One change of the preferred address moves the client at most once, so a socket whose address still differs after the move does not move again until the route changes.

Some networks block UDP. SpaceTerm has no TCP fallback under the rule against dual transports; such a network needs a VPN or tailnet route, as an unreachable WSS port did. A later hosted relay fits without changing this decision, but it means writing SpaceTerm's own relay client, because iroh's relay client is the dependency rejected here. The relay would forward encrypted QUIC datagrams between the two devices, as iroh's relays and TURN do, and never terminate TLS. noq-proto takes datagrams from any source, so the relay is a second socket path inside the carrier, and the pinned certificates still authenticate both ends.
