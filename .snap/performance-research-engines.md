# Terminal engine performance research

Initial research recorded 2026-09-25, before implementation. Every expected application resource effect below remains a hypothesis until an optimized SpaceTerm build and equal-workload comparison establish it. The baseline revision is `134d7027b2014f89d29d0f9c4d087e894f33cfbc`.

## Source and build identity

- SpaceTerm embeds the official Ghostty gitlink `b0c421fcd2e290629d4285c181b52fe2f2095f06` through local `libghostty-vt` wrappers. The Ghostty submodule is clean. The wrapper and native-build paths have no worktree edits at this audit. The native build clones the pinned tree and applies five SpaceTerm patches in `third_party/libghostty-vt-sys/patches`; see [integration notes](../docs/ghostty-integration.md) and [build script](../third_party/libghostty-vt-sys/build.rs). Recommendations concerning native behavior must be verified against that *patched build*, not an unmodified Ghostty executable.
- `mise run build:release` invokes Cargo release mode. The native build maps that to Zig `ReleaseFast` by default and uses `-Dcpu=baseline`; `LIBGHOSTTY_VT_SYS_OPTIMIZE` can override the mode. The separate `mise run deps:engine` task explicitly selects Zig `Debug`. Do not measure that task's binary as the application release configuration. See [.mise.toml](../.mise.toml), [native build script](../third_party/libghostty-vt-sys/build.rs), and [Cargo profiles](../Cargo.toml).
- WezTerm source was inspected at `b09b56c29c1e367e598b60ca266e2cc9038751e0` (GitHub `main` on 2026-09-25). It is a comparison for design choices, not a drop-in engine for SpaceTerm.
- The current wrapper sets Ghostty's `SCROLLBACK_MAX_LINES` from `TerminalOptions::max_scrollback`, but Ghostty's native constructor also retains its default `max_scrollback_bytes = 10_000`. Both limits apply. A 10,040-line, 112-character fixture retained 497 Scrollback rows, even though SpaceTerm requests 10,000 rows. This is a pre-existing effective limit; changing it would change product behavior and is outside this performance work. See [wrapper constructor](../third_party/libghostty-vt/src/terminal.rs), [Ghostty terminal defaults](https://github.com/ghostty-org/ghostty/blob/b0c421fcd2e290629d4285c181b52fe2f2095f06/src/terminal/Terminal.zig#L263-L278), and [native C constructor](https://github.com/ghostty-org/ghostty/blob/b0c421fcd2e290629d4285c181b52fe2f2095f06/src/terminal/c/terminal.zig#L855-L885).

## Existing behavior that should be kept

- SpaceTerm reads each PTY in a dedicated blocking reader with a 16 KiB buffer. A bounded eight-item channel applies backpressure, and the Terminal Session worker accepts a bounded group while preserving ordering against control commands. See [PTY reader](../src/platform/native_pty.rs), [Session reader transport and batch](../src/terminal/session.rs).
- The Terminal Session already accumulates an initial output burst for 8 ms and paces further Screen publication to about 60 Hz. Hidden or inactive Panes suppress Screen snapshots while their Terminal Sessions continue parsing bytes, handling protocol replies, and retaining metadata; restoration requests a fresh presentation. Unfocused but visible Panes remain presentable. See [schedules](../src/terminal/session/schedules.rs), [Session output](../src/terminal/session.rs), and [Pane presentability](../src/ui/terminal_pane.rs).
- SpaceTerm uses Ghostty's global and per-row dirty state. It reuses `Arc` rows that compare equal, publishes row-level content damage, avoids publishing a clean Screen, and has tests for immutable row reuse and incremental/full equivalence. This is already the right base for dirty snapshots. See [Terminal Emulator snapshot](../src/terminal/emulator.rs), [Ghostty render wrapper](../third_party/libghostty-vt/src/render.rs), and [snapshot tests](../src/terminal/emulator/tests.rs). WezTerm likewise tracks line change sequence numbers; it does not justify replacing SpaceTerm's working dirty path ([WezTerm screen source](https://github.com/wez/wezterm/blob/b09b56c29c1e367e598b60ca266e2cc9038751e0/term/src/screen.rs#L334-L347)).

## Prioritized candidates and experiments

1. **Cell text construction, likely high allocation pressure during redraws.** Each rebuilt row calls `cell.graphemes()`, which allocates a `Vec<char>` per cell, then collects those characters into a `String`; blank and wide-tail cells also create a `String`. The local wrapper already offers `graphemes_utf8(&mut String)`, which writes the UTF-8 cluster directly. Inspect [snapshot cell loop](../src/terminal/emulator.rs), [wrapper implementation](../third_party/libghostty-vt/src/render.rs). Prototype direct UTF-8 construction with exact whitespace and wide-cell behavior. Benchmark ASCII scrolling, combining marks, emoji, CJK, and large full redraws; count allocations and compare Screen snapshots and conformance results. This removes an evident intermediate allocation but the application CPU effect is unmeasured. `graphemes_utf8` can grow the destination and still leaves a required owned cell string.
2. **Idle scrollback compression, likely a memory candidate only after output settles.** The pinned Ghostty library exposes `Terminal::compression_activity()` and `Terminal::compress(Incremental)`, but `src/` has no call sites. Ghostty's own renderer waits for 250 ms of compression-relevant inactivity, performs bounded incremental steps, and schedules a pending continuation after 1 ms. The native step inspects at most eight candidate pages and tries at most one new page; full compression is explicitly unsuitable for interactive use. Compression targets offscreen complete primary-screen pages and can restore them transparently. macOS arm64 is an eligible target for retained-mapping reclamation, but success and benefit depend on page contents and the OS. See [Ghostty renderer](https://github.com/ghostty-org/ghostty/blob/b0c421fcd2e290629d4285c181b52fe2f2095f06/src/renderer/Thread.zig#L755-L857), [PageList](https://github.com/ghostty-org/ghostty/blob/b0c421fcd2e290629d4285c181b52fe2f2095f06/src/terminal/PageList.zig#L4760-L4894), [memory support](https://github.com/ghostty-org/ghostty/blob/b0c421fcd2e290629d4285c181b52fe2f2095f06/src/terminal/mem.zig#L29-L62), and [local wrapper](../third_party/libghostty-vt/src/terminal.rs). Add a deadline and continuation to the Terminal Session worker, serialized with all emulator operations, keyed to the activity token rather than every wake. Compare settled physical footprint after filling 10,000 Scrollback rows, foreground idle, hidden idle, and repeated Scrollback search/restore. Also measure CPU and wakeups added by compression. Never alter the logical Scrollback limit or compress during active input. Existing `MAX_SCROLLBACK_ROWS = 10_000` and retained Rust snapshots limit the possible process-level benefit.
3. **PTY and OSC path, likely throughput/allocation candidate.** The reader allocates a new `Vec<u8>` for every read, and each read sends both one byte event and one `ReaderReady` command. The OSC 52 filter scans each byte and builds owned `Terminal` effects; an OSC 52 sequence also clones its raw bytes. This preserves denial and ordering, but may dominate plain-text output before Ghostty parses it. See [PTY reader](../src/platform/native_pty.rs), [Session transport/output loop](../src/terminal/session.rs), and [OSC 52 filter](../src/terminal/native_services/osc52.rs). First profile CPU and allocation counts under equal-byte plain text, escape-heavy output, split OSC sequences, and many small writes. If material, prototype buffer reuse or a slice-oriented filter with an explicit ordered reply boundary. Maintain the bounded queue, control-command fairness, OSC 52 denial, callback order, and PTY backpressure. Do not increase read or batch sizes on intuition alone.
4. **Active Terminal Find, potentially severe only while Find remains open under output.** Every nonempty feed invalidates Find. The next Screen snapshot calls `refresh`, which rebuilds a searchable corpus across the active screen and Scrollback for a nonempty query. This can repeatedly scan up to the configured 10,000 Scrollback rows, and accessing compressed pages could restore history. See [feed invalidation](../src/terminal/emulator.rs), [Find refresh/corpus](../src/terminal/find.rs). Profile a fixed Find query while new lines arrive at several rates and Scrollback depths. If confirmed, test a bounded incremental index or limit rescanning to changed logical lines while preserving matches across wrapping, reflow, alternate screen, selection, and UTF-8 boundaries. This is a higher semantic-risk change than cell encoding.
5. **Snapshot metadata and per-cell FFI, profile before changing.** Each snapshot constructs color/palette and graphics state before its clean-frame exit and traverses row metadata even if only cursor or title damage exists. A dirty row makes several wrapper calls per cell and performs hyperlink detection after materializing the row. Those calls might cost more than UTF-8 allocation on some workloads, but there is no timing evidence. See [snapshot prelude and row walk](../src/terminal/emulator.rs). Measure clean cursor updates, title-only updates, partial-row updates, and hyperlink-heavy output. If cost is material, narrow the clean path or expose a batched native row read through the local wrapper; keep Ghostty's dirty-state consumption and all color, graphics, selection, hyperlink, and accessibility semantics intact.

WezTerm demonstrates a different batching tradeoff: it reads PTY bytes into a 1 MiB buffer, parses into actions on a separate thread, coalesces fragments for up to a configured 3 ms by default, and uses a default 128 KiB parser buffer to bound action-application latency. It flushes on synchronized-output transitions and at EOF. See [mux source](https://github.com/wez/wezterm/blob/b09b56c29c1e367e598b60ca266e2cc9038751e0/mux/src/lib.rs#L118-L259) and [defaults](https://github.com/wez/wezterm/blob/b09b56c29c1e367e598b60ca266e2cc9038751e0/config/src/config.rs#L1675-L1682). SpaceTerm already batches publication and processes Ghostty output on a separate Terminal Session worker. WezTerm's buffer sizes and delay should therefore be treated as comparison points, not performance targets or evidence of a SpaceTerm bottleneck.

## Measurement and correctness gates

Use the optimized source build and [measurement protocol](../docs/performance.md). Establish the same fixture, geometry, output byte count, and delivered throughput for baseline and each candidate. Collect per-process CPU, wakeups, physical footprint, allocation profile, and snapshot/paint counts where possible; use native profiling for GPU work. Record absent metrics explicitly. The release build had no completed runtime measurements when this research started, so no percentage improvement is asserted here.

The ignored native fixture `performance_compression`, run with `mise run bench:one performance_compression`, used the current wrapper's exact options on macOS arm64. It filled 10,040 lines in a 120-by-40 grid and observed 497 retained Scrollback rows. Four fresh release test processes completed incremental compression in two calls. Total call time was 0.053–0.098 ms; the largest single call had the same range. `proc_pid_rusage` physical footprint fell by 393,216–409,600 bytes (0.375–0.391 MiB) between pre-compression and post-compression samples. Native resident bytes rose by about 0.4 MiB under Darwin's reusable-memory accounting, so resident size is not the benefit measure here. A complete selected copy of the retained history was byte-identical before compression, immediately after, and after scrolling to the top and bottom. This is an isolated engine measurement in a test process, not a SpaceTerm process, CPU, GPU, or wakeup result.

The implementation trial adds one serialized Terminal Session compression step after 250 ms of compression-relevant idle time, continues a pending pass with a 1 ms deadline, and gives queued commands priority. Input and output postpone a pending pass. Complete stays dormant until the native activity token changes. Unsupported or an API error disables the optional work for that Terminal Session. Focused tests cover scheduling, queued-input fairness, and retained-history Find/selection equivalence. The full application resource comparison and broader regression suite remain pending; they determine whether this trial stays in the change.

For cell and batching changes, retain tests for split VT sequences, synchronized output, OSC 52 ordering and denial, terminal replies, hidden Terminal Session processing, and byte-for-byte screen equivalence. For compression, validate Scrollback search/copy, reflow, selection anchors, rapid hide/restore, and Pane closure. Candidate benefit should be accepted only after end-to-end resource measurements, since fewer allocations or less native resident history can be hidden by rendering, child processes, or retained snapshots.
