# Admit local accounts and paired remote clients

Account-local IPC admits the server's owning account through peer-account, private-endpoint and application-identity checks. It trusts processes running as that account and requires no pairing or credential store. Build identities prevent accidental cross-use, not hostile owner processes.

Every remote client uses QUIC with pinned server trust and a deliberately enrolled device credential. Account-local and paired clients can control terminal work, edit Server Settings, and administer the running server: read its status, Stop, Restart, Update and Change Network Access. A paired client already holds the owning account's authority through terminal control, so no separate administration grant exists. Start, setup, uninstallation, automatic startup, linger, Invite Device, approval, removal of other devices, End All Sessions and System Permission setup require the server's own machine. So does a Network Access change that leaves no connected Paired Device a route, such as turning Network Access off; [ADR 0057](0057-administer-servers-over-the-service-lane.md) defines that check. Keeping these actions there prevents self-lockout and keeps code comparison physical. It is not a security boundary: a paired client can run `spaceterm server pair` in a Pane on that server. A paired client can revoke its own pairing. [ADR 0038](0038-unpair-devices-without-blocking-local-connection-removal.md) defines pairing-specific revocation. [ADR 0029](0029-enroll-remote-servers-through-add-server.md) defines enrollment.

Client Identity distinguishes views, attachments, Pane control and operations; Client Name labels control for other clients. Neither grants authority. Connection, Terminal Session, control and attachment generations independently fence operations.

Native service actions run with owning-account operating-system authority on the server's machine. [ADR 0057](0057-administer-servers-over-the-service-lane.md) delegates admitted remote actions to a transient helper with that authority. Remote values grant no client-local file access. The desktop's own Desktop Channel admits only its account by peer credentials and opens files only for Local Panes under [ADR 0060](0060-open-files-and-show-work-in-the-desktop-over-the-desktop-channel.md). Signed-artifact verification, deliberate Stop, bounded process ownership and reconciliation of started Git writes remain required.

[ADR 0052](0052-carry-paired-connections-over-quic.md) owns the paired transport.
