# Install and pair servers from their own command line

The primary remote setup path runs on the server's own machine: `install.sh --headless`, `spaceterm server setup`, then `spaceterm server pair`. Another device joins the Invitation Link through the desktop's Add Server or `spaceterm connection add`. [ADR 0029](0029-enroll-remote-servers-through-add-server.md) owns enrollment trust and the optional desktop SSH Setup method.

Setup obtains Linux linger authorization when needed, installs the service from the launcher's installation, starts the server unless deliberately stopped, and sets Network Access. [The setup handler](../../crates/spaceterm-cli/src/server/setup.rs) reports its steps and changes only preferences its flags name. Without a terminal, Network Access must be explicit and linger authorization must already exist. [ADR 0030](0030-start-servers-at-boot-independently-of-clients.md) owns startup policy and the Mac GUI-session requirement. The installer also owns uninstallation; server help supplies its invocation.

`server pair` prints the Invitation Link and waits for its exact claim. It uses the invitation management contracts in [ADR 0029](0029-enroll-remote-servers-through-add-server.md). `--address HOST[:PORT]` supplies the advertised authority. [The pairing flow](../../crates/spaceterm-cli/src/server/pair.rs) polls every two seconds with its own invitation ID and waits no longer than five minutes for a claim. The person types the Comparison Code displayed on the joining device. The comparison prompt waits for input, EOF or interruption. A wrong code rejects the claim. A failed attempt tries to withdraw its invitation. Approval also prints the paired device on stdout. JSON, no-input mode or absence of a terminal fails before creating an invitation.

`connection add` reads the link from stdin or a hidden prompt, never from arguments. `--join` authorizes noninteractive enrollment; the joining client still displays its authenticated Comparison Code for approval on the server's machine. `--address` replaces only the invitation's endpoint and preserves its server identity, certificate and proof-key pin. CLI Saved Connections and credentials stay separate from the desktop's. [The connection handler](../../crates/spaceterm-cli/src/connection.rs) owns consent and output; [shared enrollment](../../crates/spaceterm-connections/src/enrollment.rs) persists exact cancellation authority before any network effect and commits the Saved Connection only after enrollment succeeds.

Confirmed connection removal removes the active local record before attempting server revocation. Restricted self-revocation and credential cleanup remain pending until confirmed. Later `connection add` and `connection remove` commands retry them. `connection list` reads active and pending records and held counts without opening credentials, admitting a connection or retrying cleanup. [ADR 0038](0038-unpair-devices-without-blocking-local-connection-removal.md) owns exact revocation and enrollment cleanup.

[ADR 0004](0004-resolve-application-directories-by-xdg-convention.md) owns credential storage and its requirements for the CLI's client and server roles.
