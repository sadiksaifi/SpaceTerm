# Open files and show work in the desktop over the Desktop Channel

Inside a Local Terminal Session, `spaceterm open PATH` opens a local file with its default application, and `spaceterm open PATH --preview` presents its File Preview. `spaceterm show [--workspace W] [--worktree T] [--tab B] [--pane P]` brings the desktop's own view to a Workspace, Tab or Pane. Both commands ask the desktop on the same machine and account over the Desktop Channel. The server never relays them, and no other client's view moves. [The command tree](../../crates/spaceterm-cli/src/args.rs) owns the grammar; [the CLI desktop module](../../crates/spaceterm-cli/src/desktop.rs) owns the requests and their output.

## Channel

The desktop listens on a stream socket named `d` in a directory `<identity>-desktop` inside the operating system's own directory for the account: the user cache directory `confstr(_CS_DARWIN_USER_CACHE_DIR)` on macOS, and `/run/user/<uid>` on Linux. Neither depends on a launch environment, so a shell the server service starts finds the desktop the person launched. No other account can create or occupy either, unlike a predictable name in the shared `/tmp`. The account root must be a real directory the account owns that no other account can enter. Linux without `/run/user/<uid>`, as without a login session, has no Desktop Channel: the desktop listens nowhere and the CLI reports `desktop_unavailable`. The socket path stays within the host's `sun_path` limit. [Directory resolution](../../crates/spaceterm-directories/src/server.rs) owns the path. The endpoint directory must be owned by the account, have mode 0700 and contain no symbolic link. The desktop holds `lock` in it for as long as it listens. A second desktop process of the same identity and account finds the lock held and listens nowhere. The lock also proves that a socket left by an ended desktop is stale, so the next desktop replaces it. [The POSIX endpoint](../../src/platform/unix_desktop_channel.rs) owns the directory, lock, socket and peer checks.

Both ends require the peer to run as their own account. The desktop reads `getpeereid` on macOS and `SO_PEERCRED` on Linux. It closes a connection from another account unread and answers nothing. The CLI checks the listener the same way before it sends a request. The peer check is the authority. The application identity in each request only prevents accidental cross-use between SpaceTerm and SpaceTerm Development, as [ADR 0027](0027-trust-paired-clients-equally.md) describes for account-local server admission.

One connection carries one request. The CLI writes one JSON document and half-closes the socket. The desktop writes one reply and closes. Each message is at most 16 KiB. The `spaceterm.desktop.v1` schema is replaced outright on change; the desktop answers another schema or application identity with `incompatible`. [The channel contract](../../src/desktop_channel.rs) owns these messages.

Every connect, read and write ends by an absolute deadline, recomputed before each operation; a single read or write waits at most 100 ms before it rechecks. The CLI's deadline is its `--timeout`, by default 10 seconds for `open` and the work commands' 30 seconds for `show`. An interrupt brings it to the settlement instant of [ADR 0055](0055-define-the-cli-output-contract-and-scope-model.md). The request carries how long the CLI waits. The desktop gives a client two seconds to deliver its whole request and itself two seconds to deliver its reply, so a client that trickles bytes holds the channel for no longer. A request may act only until 250 ms before its client gives up, and never later than 60 seconds after it arrived. A request past that instant performs nothing and gets no answer. The desktop thread serves one connection at a time and hands each request to the GPUI main thread, which answers each on its own, so a file still being checked holds no other request back.

The request is the command's dispatched effect under ADR 0055. Ctrl-C before it ends the command at once. After it, the CLI waits for the answer within the interrupt grace: an answer that arrives is reported with exit 130, and none leaves `outcome_unconfirmed` with exit 7. A desktop that received the whole request and closed without answering also leaves `outcome_unconfirmed`. Without an interrupt, reaching the deadline reports `timeout`, because the desktop acts on nothing after it.

## Targets

Requests carry exact server, Workspace, Tab, Pane and Terminal Session IDs. They are fences that select what the desktop presents and grant nothing. The desktop compares the server ID with its local server's admitted ID, or with the ID a paired route pins. A request for work it does not present is refused as `not_shown`. Nothing in the view moves before every named level is found. With several desktops attached to one server, only the desktop on the Session's machine and account receives the request; a desktop on another machine cannot be reached. One desktop presents one Workspace Window under [ADR 0046](0046-keep-one-workspace-window-per-desktop-client.md), so that window answers. A desktop that presents no Workspace Window refuses with `not_shown`.

`open` reads `SPACETERM_IDENTITY`, `SPACETERM_SERVER_ID`, `SPACETERM_PANE` and `SPACETERM_SESSION` from [ADR 0058](0058-derive-agent-identities-at-admission.md)'s Session context. It needs no server connection. Without a complete context for this executable's identity it fails with `context_unavailable`. The desktop requires the Pane to hold that exact live Terminal Session, from the close facts in its latest inventory. A changed Session is `not_shown`.

`show` resolves its target through [ADR 0055](0055-define-the-cli-output-contract-and-scope-model.md)'s scope resolver against the server's Workspace Inventory, as `list` does. It acts on the deepest explicit level: a Pane, a Tab, or a Workspace. A Worktree selects one of its Tabs. With no selector, the current Pane is shown. The desktop activates the Workspace with its restored Focused Pane, then the Tab or Pane when named, and brings its window forward. It never creates a Workspace Attachment: a Workspace this desktop has not attached is `not_shown`.

Both commands accept only the local route. A `--server` or `SPACETERM_SERVER` naming a paired server fails with `local_only` before any effect.

## Local file authority

Only a Local Pane's own filesystem authority opens a file. The account-local server's Pane opener holds that authority; a paired route's opener holds none. A request whose Pane belongs to a paired server is refused as `remote_session` before its path is read. Remote values therefore never reach the local filesystem, even when a forwarded environment names a server this desktop presents remotely.

The CLI resolves a relative path against its own working directory and sends the absolute path. The GPUI main thread never touches the file, because a network mount can block filesystem calls without bound. It checks the Session as above, then a worker thread validates the path with [Local Filesystem Authority](../../src/platform/local_filesystem.rs): it must be absolute, UTF-8, at most 4 KiB and name a regular file that this account can open for reading. Anything else is `file_unavailable`. For opening, the worker also builds the revalidated `file://` URL. At most four checks run at once, so an unresponsive mount holds at most four worker threads; another request meanwhile is refused as `busy`. The main thread polls for the worker's answer, then checks again that the Session's Pane still presents that live Terminal Session before the native handoff, and refuses `not_shown` otherwise. Opening hands the URL to the host. File Preview first shows the Session's Pane, because the preview presents for that Pane, then submits the validated target to the Pane's presenter. That presenter revalidates at its final native handoff on the main thread, as it does for every File Preview, just after the worker's check succeeded. A synchronous preview failure is `preview_unavailable`; a deferred failure is presented in the Pane. [The desktop request handler](../../src/ui/workspace_manager/desktop_requests.rs) owns these checks.

## Failures

The desktop's refusals are `not_shown`, `remote_session`, `file_unavailable`, `preview_unavailable`, `busy` and `incompatible`; the CLI reports `busy` as `desktop_busy`. The CLI reports no listening desktop as `desktop_unavailable`, an endpoint that is not private as `unsafe_storage`, a listener of another account as `authentication_refused`, an unanswered request as `outcome_unconfirmed`, no reply by the deadline as `timeout`, and an incompatible or incomplete exchange as `desktop_incompatible`. Each carries a fixed classification only. Paths, IDs and native errors never enter errors or diagnostics. Successful `open` output reports the absolute path, Pane and Session as requested operational data on stdout.
