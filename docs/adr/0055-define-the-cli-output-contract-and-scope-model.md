# Define the CLI output contract and scope model

The CLI serves people and automation through the same commands. Text is the default. `--json` emits the versioned `spaceterm.cli.v1` envelope and requires noninteractive behavior. Only `connection add --json` streams NDJSON: its Comparison Code event precedes the final envelope. [The output contract](../../crates/spaceterm-cli/src/contract.rs) owns the envelope, per-command data, fixed errors, warnings and exit mappings. Fields may be added within a schema version; removing, renaming or retyping one replaces that version outright.

`data` is always an object. Recovered results add `data.recovered_operations` only when it is nonempty. `server` is null for connection-store commands and failures before server identification; an identified server has its full ID. `command` is the dotted command path, including the recognized portion on a parse failure. A confirmation preview has both `status: "confirmation_required"` and `error.code: "confirmation_required"`, and exits 3. A text hint that names a whole command repeats the resolved `--server` route and the effective `--as` agent, as [the server command context](../../crates/spaceterm-cli/src/server.rs) builds it, so a copied confirmation reaches the same server as the same actor. [Shell words](../../crates/spaceterm-cli/src/shell.rs) single-quote each printed argument that holds a shell character, such as the brackets of an IPv6 address, so the line pastes into `sh`, Bash and Zsh unchanged.

Errors and warnings contain fixed classifications and bounded typed metadata. Labels, directories, candidate descriptions and captured terminal output are requested operational data on stdout, including when a command fails. They never enter stderr errors, warnings or diagnostics. Usage errors can name an argument from [the command tree](../../crates/spaceterm-cli/src/args.rs), never a rejected value or unknown name. Target errors name the failed level; a scope mismatch identifies both that level and its explicit parent. Exit codes distinguish success (0), failure (1), usage (2), action required (3), target (4), unavailable (5), deadline (6), unconfirmed (7), interruption (130) and broken stdout pipe (141). Usage validation happens before effects. Exit precedence is unconfirmed, interrupted, usage, unavailable, action required, target, deadline, failed, then success. A service receipt of `not_performed` reports `operation_failed` and exits 1. A confirmed running command that reaches its deadline reports timeout without cancelling the command. A broken stdout pipe exits silently. Text-mode warnings use the output contract's shared renderer, including before an interactive confirmation.

[One interrupt module](../../crates/spaceterm-cli/src/interrupt.rs) owns SIGINT for every command except `server run` and `server provision`, as selected by [the executable entry point](../../crates/spaceterm-cli/src/main.rs). Before dispatch, interruption emits the `interrupted` envelope and exits 130 without an effect. After dispatch, waits must stop within five seconds of the interrupt. Writing the result may take one second more. A second interrupt ends output at once. The renderer preserves the outcome and exits 130 unless it remains unconfirmed, which keeps exit 7. [Pairing](../../crates/spaceterm-cli/src/server/pair.rs) and [connection commands](../../crates/spaceterm-cli/src/connection/terminal.rs) cooperate with the same module to finish or withdraw their pending work.

Targeting selects one server first: `--server`, then `SPACETERM_SERVER`, then `local`. Child selectors never search other servers. Explicit selectors resolve against one Workspace Inventory and repository snapshot; their memberships must agree. Compatible current Terminal Session context fills a missing level only when nothing explicit at or below that level supplies it. Single candidates fill the rest before command-specific creation defaults. Ambiguity stops the operation and returns candidates with handles to copy. Worktrees have path identity; other work objects and saved routes support IDs. Every resolved level reports where its value came from. [The scope resolver](../../crates/spaceterm-cli/src/scope.rs) owns selection; [ADR 0058](0058-derive-agent-identities-at-admission.md) owns the Session context.

Destructive commands require an explicit ID, exact handle or validated current context at the acted-on level. A singleton or substring cannot choose that target. Confirmation binds the exact action and its affected work; changed observations require a new preview. Local connection-store commands reject a remote server selector before effects.

## Paths and creation

`workspace pin DIR`, `--directory`, `--path`, Worktree `path:` selectors and `pane run --directory` use the selected server's path rules. A paired route requires an absolute path or a literal `~/` prefix expanded with the server account's home. Quote that prefix, as in `'~/Projects/api'`, so the invoking shell does not expand it. Other remote relative paths, including bare `~` and `~user`, are usage errors. On the local route, relative paths use the CLI's working directory. Empty paths and paths containing NUL are refused. [Path resolution](../../crates/spaceterm-cli/src/work/paths.rs) never treats a remote path as authority for local file access.

`workspace pin DIR` and `workspace unpin` set and clear the selected Workspace's Pinned Directory through the desktop's existing versioned `PinWorkspace` mutation. They use ordinary mutating Workspace scope and require no destructive confirmation. A conflict requires another explicit invocation. Their results report the refreshed Workspace reference, inventory revision and `data.pinned_directory`, which is null when unpinned. Existing Terminal Sessions keep their directories. New Terminal Sessions use the creation rules below.

The desktop and CLI share [organization plans](../../crates/spaceterm-server/src/organize.rs). The server's [hierarchy](../../crates/spaceterm-server/src/hierarchy.rs) and [Worktree operations](../../crates/spaceterm-server/src/worktree.rs) choose and validate Starting Directories.

| Creation | Source and Starting Directory |
| --- | --- |
| Workspace | `--directory`, otherwise the server account's home. |
| Tab | The current Pane in that Workspace, otherwise the Root Tab's Root Pane. An explicit Worktree wins; otherwise the source Tab's Worktree is inherited. A Worktree Tab starts in that Worktree. An ordinary Tab starts at the Pinned Directory, otherwise the source Pane's confirmed directory, otherwise its Starting Directory. |
| Split | The current Pane in that Tab, otherwise its Root Pane. Starts at the Tab's Worktree directory, otherwise the Pinned Directory, otherwise the source Pane's confirmed directory, otherwise its Starting Directory. |
| Worktree | The server validates the requested path or resolves its Worktree Location template. Creation opens exactly one Tab under [ADR 0058](0058-derive-agent-identities-at-admission.md)'s shared creation control policy. `--open` opens no second Tab. |

Inside a Session, `tab create --workspace api` retains the current Worktree when that Pane belongs to `api`. `--worktree main-worktree` selects the Main Worktree instead. Every successful Workspace, Tab, Split and Worktree create result reports the server-chosen Starting Directory in `data.directory`, as assembled by [the work executor](../../crates/spaceterm-cli/src/work/execute.rs).

Closing all Tabs of a Worktree uses the shared fallback plan. When this would empty the Workspace, it opens a Tab in another usable Worktree before closing the target Tabs. The Main Worktree is preferred, followed by Git's order. The target, missing directories and bare checkouts are excluded. With no destination, the operation fails before closing anything. Worktree removal uses the same destination policy. [The CLI Tab planner](../../crates/spaceterm-cli/src/work/tab.rs) and [desktop repository adapter](../../src/ui/workspace_manager/shared_repositories.rs) use these shared operations.

## Run admission

`pane run` checks its `--session` fence before claiming a Pane, so a mismatched Session cannot start a shell or take control. [The run handler](../../crates/spaceterm-cli/src/io/run.rs) checks the claimed Session again before admission. Run admits one verbatim shell command against an exact Terminal Session, control lease, owner-marked prompt and empty input line. Bracketed paste inserts it without argv joining. Line Mode alone cannot establish a shell prompt. Input written after a command's finish and before its next prompt counts against that next prompt, so typeahead cannot appear to be an empty editor. [Terminal metadata](../../src/terminal/metadata.rs) tracks the owner markers and input count; [run admission](../../src/terminal/emulator/run.rs) checks them.

Run requires SpaceTerm integration in Bash 5.1 or later, Zsh, Fish, Elvish or Nushell, with an owner-marked prompt and bracketed paste enabled. Bash before 5.1 and `sh` are unsupported. Admission checks markers and modes rather than a shell version string. The CLI waits for a new shell's first integrated prompt within the startup deadline before refusing missing integration. A line editor can enable bracketed paste after its prompt marker, so [the CLI run handler](../../crates/spaceterm-cli/src/io/run.rs) retries `NoBracketedPaste` refusals for up to one second within the command deadline. Such a refusal writes no input. A pending run, a nonempty editor or absence of a prompt reports `not_at_prompt`.

A server receipt correlates command start and finish; a missing exit status remains unconfirmed. Resolving a lost reply never resends terminal input. Captured output is bounded terminal presentation and reports gaps or coalescing. `pane send` reports delivery only when the server acknowledges that its input serial reached the PTY. Run journals, concurrent runs and receipt retention follow [ADR 0058](0058-derive-agent-identities-at-admission.md). [ADR 0059](0059-observe-panes-without-taking-control.md) owns the server's Terminal I/O admission boundary.
