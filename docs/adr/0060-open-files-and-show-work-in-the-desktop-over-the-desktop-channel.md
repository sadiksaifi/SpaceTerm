# Open files and show work in the desktop over the Desktop Channel

Inside a Local Terminal Session, `spaceterm open PATH` opens a local file with its default application, and `spaceterm open PATH --preview` presents its File Preview. `spaceterm show [--workspace W] [--worktree T] [--tab B] [--pane P]` brings the desktop's own view to a Workspace, Tab or Pane. Both commands ask the desktop on the same machine and account over the Desktop Channel. The server never relays them, and no other client's view moves. [The command tree](../../crates/spaceterm-cli/src/args.rs) owns the grammar; [the CLI desktop module](../../crates/spaceterm-cli/src/desktop.rs) owns the requests and their output.

## Channel

The desktop listens on a stream socket named `d` in `/private/tmp/<identity>-desktop-<uid>` on macOS and `/tmp/<identity>-desktop-<uid>` on Linux. Like the server's runtime directory, the path ignores launch environments, so a shell the server service starts finds the desktop the person launched. [Directory resolution](../../crates/spaceterm-directories/src/server.rs) owns the path. The directory must be owned by the account, have mode 0700 and contain no symbolic link. The desktop holds `lock` in it for as long as it listens. A second desktop process of the same identity and account finds the lock held and listens nowhere. The lock also proves that a socket left by an ended desktop is stale, so the next desktop replaces it. [The POSIX endpoint](../../src/platform/unix_desktop_channel.rs) owns the directory, lock, socket and peer checks.

Both ends require the peer to run as their own account. The desktop reads `getpeereid` on macOS and `SO_PEERCRED` on Linux. It closes a connection from another account unread and answers nothing. The CLI checks the listener the same way before it sends a request. The peer check is the authority. The application identity in each request only prevents accidental cross-use between SpaceTerm and SpaceTerm Development, as [ADR 0027](0027-trust-paired-clients-equally.md) describes for account-local server admission.

One connection carries one request. The CLI writes one JSON document and half-closes the socket. The desktop writes one reply and closes. Each message is at most 16 KiB. The `spaceterm.desktop.v1` schema is replaced outright on change; the desktop answers another schema or application identity with `incompatible`. The CLI waits at most 10 seconds for a reply. [The channel contract](../../src/desktop_channel.rs) owns these messages. The desktop thread hands each request to the GPUI main thread and waits for its answer, so the channel serves one request at a time.

## Targets

Requests carry exact server, Workspace, Tab, Pane and Terminal Session IDs. They are fences that select what the desktop presents and grant nothing. The desktop compares the server ID with its local server's admitted ID, or with the ID a paired route pins. A request for work it does not present is refused as `not_shown`. Nothing in the view moves before every named level is found. With several desktops attached to one server, only the desktop on the Session's machine and account receives the request; a desktop on another machine cannot be reached. One desktop presents one Workspace Window under [ADR 0046](0046-keep-one-workspace-window-per-desktop-client.md), so that window answers. A desktop that presents no Workspace Window refuses with `not_shown`.

`open` reads `SPACETERM_IDENTITY`, `SPACETERM_SERVER_ID`, `SPACETERM_PANE` and `SPACETERM_SESSION` from [ADR 0058](0058-derive-agent-identities-at-admission.md)'s Session context. It needs no server connection. Without a complete context for this executable's identity it fails with `context_unavailable`. The desktop requires the Pane to hold that exact live Terminal Session, from the close facts in its latest inventory. A changed Session is `not_shown`.

`show` resolves its target through [ADR 0055](0055-define-the-cli-output-contract-and-scope-model.md)'s scope resolver against the server's Workspace Inventory, as `list` does. It acts on the deepest explicit level: a Pane, a Tab, or a Workspace. A Worktree selects one of its Tabs. With no selector, the current Pane is shown. The desktop activates the Workspace with its restored Focused Pane, then the Tab or Pane when named, and brings its window forward. It never creates a Workspace Attachment: a Workspace this desktop has not attached is `not_shown`.

Both commands accept only the local route. A `--server` or `SPACETERM_SERVER` naming a paired server fails with `local_only` before any effect.

## Local file authority

Only a Local Pane's own filesystem authority opens a file. The account-local server's Pane opener holds that authority; a paired route's opener holds none. A request whose Pane belongs to a paired server is refused as `remote_session` before its path is read. Remote values therefore never reach the local filesystem, even when a forwarded environment names a server this desktop presents remotely.

The CLI resolves a relative path against its own working directory and sends the absolute path. The desktop validates it with [Local Filesystem Authority](../../src/platform/local_filesystem.rs): it must be absolute, UTF-8, at most 4 KiB and name a regular file that this account can open for reading. Anything else is `file_unavailable`. Opening hands the revalidated `file://` URL to the host. File Preview first shows the Session's Pane, because the preview presents for that Pane, then submits the revalidated target to the Pane's presenter. A synchronous preview failure is `preview_unavailable`; a deferred failure is presented in the Pane. [The desktop request handler](../../src/ui/workspace_manager/desktop_requests.rs) owns these checks.

## Failures

The desktop's refusals are `not_shown`, `remote_session`, `file_unavailable`, `preview_unavailable` and `incompatible`. The CLI reports no listening desktop as `desktop_unavailable`, an endpoint that is not private as `unsafe_storage`, a listener of another account as `authentication_refused`, no reply in time as `timeout`, and an incompatible or incomplete exchange as `desktop_incompatible`. Each carries a fixed classification only. Paths, IDs and native errors never enter errors or diagnostics. Successful `open` output reports the absolute path, Pane and Session as requested operational data on stdout.
