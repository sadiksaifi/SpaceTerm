## Launch critical path

1. `platform::macos_composition::main` dispatches the AskPass helper, then captures startup dependencies and composes the host before `app::run` creates GPUI. [`src/platform/macos_composition.rs:16`](../src/platform/macos_composition.rs) and [`src/app.rs:860`](../src/app.rs). Any synchronous work here delays every native frame.
2. `StartupDependencies::capture` runs `SshCapabilityProbe::probe_blocking` before GPUI construction. The probe executes `/usr/bin/ssh -V` through the supervised process path, with a five-second deadline and bounded stdout and stderr. [`src/app.rs:78`](../src/app.rs), [`src/ssh/command.rs:19`](../src/ssh/command.rs), [`src/ssh/command.rs:143`](../src/ssh/command.rs), [`src/ssh/process.rs:917`](../src/ssh/process.rs). A separate 20-run warm sample of the raw `/usr/bin/ssh -V` command on this host had a 5.03 ms median and 4.86-10.37 ms range. This is only the child command cost; it excludes SpaceTerm's supervision and all UI work. A slow or hung probe can hold first frame substantially longer.
3. `start_application` synchronously reads and parses the Settings Document, installs appearance, initializes controls and native Services, and opens the first Workspace window. [`src/app.rs:897`](../src/app.rs), [`src/settings.rs:205`](../src/settings.rs). `appearance_runtime::install` enumerates every installed font and resolves/measures four glyphs in each family before the window opens. [`src/ui/appearance_runtime.rs:89`](../src/ui/appearance_runtime.rs), [`src/ui/appearance_runtime.rs:299`](../src/ui/appearance_runtime.rs). The cost will vary with the host's font collection. No per-stage timing exists yet.
4. `WorkspaceManager::new_with_adapters` validates the home directory, builds the initial Workspace, Tab, and Pane, and eagerly creates the Remote Workspace backend. [`src/ui/workspace_manager.rs:346`](../src/ui/workspace_manager.rs), [`src/ui/workspace_manager.rs:3515`](../src/ui/workspace_manager.rs). The first Pane starts its Terminal Session asynchronously at the worker boundary, so the native frame and usable shell are separate milestones. [`src/terminal/session/launch.rs:185`](../src/terminal/session/launch.rs), [`src/terminal/session/launch.rs:299`](../src/terminal/session/launch.rs). Opening the window still does synchronous Pane construction and font cell measurement. [`src/ui/terminal_pane.rs:574`](../src/ui/terminal_pane.rs).

## Terminal Session resources

Each live Pane owns one Terminal Session worker (`spaceterm-terminal`), one blocking PTY reader (`spaceterm-pty-reader`), and one termination supervisor (`spaceterm-pty-termination`). The worker owns the Terminal Emulator and queues; the reader blocks on PTY input and the supervisor blocks for one close or stop command. [`src/terminal/session/launch.rs:327`](../src/terminal/session/launch.rs), [`src/platform/native_pty.rs:206`](../src/platform/native_pty.rs), [`src/platform/native_pty.rs:390`](../src/platform/native_pty.rs). Thus 1, 4, and 16 idle Panes imply 3, 12, and 48 such threads before GPUI, native framework, or remote transport threads. This is a source-derived count, not a measured memory cost. Thread stack reservations are not equivalent to physical footprint.

The PTY reader uses a 16 KiB buffer and a bounded eight-event queue, so at most eight full reader chunks, or 128 KiB of queued PTY bytes, wait on that lane per Pane. The UI event queue holds two events and can replace an older screen; metadata notifications and accessibility have separate bounded/coalesced paths. [`src/platform/native_pty.rs:14`](../src/platform/native_pty.rs), [`src/terminal/session.rs:60`](../src/terminal/session.rs), [`src/terminal/session.rs:705`](../src/terminal/session.rs), [`src/terminal/session/launch.rs:320`](../src/terminal/session/launch.rs), [`src/terminal/session.rs:1971`](../src/terminal/session.rs). Do not present queue removal as a memory fix without showing equal delivered bytes, terminal replies, and input latency. The control command lane is unbounded (`mpsc::channel`); inspect its high-rate producers under load before changing its ordering or backpressure. [`src/terminal/session/launch.rs:314`](../src/terminal/session/launch.rs), [`src/terminal/session.rs:723`](../src/terminal/session.rs).

Pane close requests termination and detaches the worker handle so the GPUI caller does not block. The worker later owns Native PTY reader joining and termination cleanup. [`src/terminal/session.rs:465`](../src/terminal/session.rs), [`src/terminal/session.rs:692`](../src/terminal/session.rs), [`src/platform/native_pty.rs:367`](../src/platform/native_pty.rs). Measure thread count, file descriptors, child processes, and settled footprint through repeated create/close cycles. A transient post-close thread count is expected; persistent growth requires investigation. A shared worker or supervisor would alter isolation, ordering, shutdown, and race handling, so pursue it only if Pane scaling shows material physical memory or wakeup cost. Retain off-thread, idempotent termination and bounded shutdown.

The worker uses `recv_timeout` on the nearest deadline. Hidden-input inspection has an immediate first check, a 200 ms follow-up after transitions, then a 30-second idle interval; this preserves detection when a program changes terminal echo without output. [`src/terminal/session.rs:1062`](../src/terminal/session.rs), [`src/terminal/session/schedules.rs:9`](../src/terminal/session/schedules.rs), [`src/terminal/session/schedules.rs:889`](../src/terminal/session/schedules.rs). At idle the fallback can create roughly one wakeup per 30 seconds per Pane, but that estimate excludes other deadlines and native work. Measure before touching it. Removing the fallback would lose silent hidden-input detection. Presentation already uses an 8 ms accumulation and 16,667 µs cadence, and graphics animation deadlines are disabled when a Pane is not presentable. [`src/terminal/session/schedules.rs:11`](../src/terminal/session/schedules.rs), [`src/terminal/session/schedules.rs:191`](../src/terminal/session/schedules.rs). Hidden Sessions must still parse output and emit replies; unfocused visible windows must still present output.

## Remote process resources

Each supervised SSH child has a stderr reader and a dedicated reaper thread. Its launch also creates a short-lived spawn thread. [`src/ssh/process.rs:764`](../src/ssh/process.rs), [`src/ssh/process.rs:777`](../src/ssh/process.rs), [`src/ssh/process.rs:831`](../src/ssh/process.rs). Captured SSH utility commands can create separate bounded stdout/stderr reader threads and poll child status every 10 ms while active. [`src/ssh/process.rs:868`](../src/ssh/process.rs), [`src/ssh/process.rs:985`](../src/ssh/process.rs), [`src/ssh/process.rs:1109`](../src/ssh/process.rs). The control connection's 100 ms readiness checks and two 10 ms cancellation/authentication watchers run during connection setup, so they are not durable idle wakeups. [`src/ssh/control_connection.rs:80`](../src/ssh/control_connection.rs), [`src/ssh/control_connection.rs:283`](../src/ssh/control_connection.rs), [`src/ui/native_remote_workspace_flow_backend.rs:411`](../src/ui/native_remote_workspace_flow_backend.rs). A ready Control Connection does retain a `spaceterm-ssh-supervisor` thread that sleeps and polls child status every 10 ms, or about 100 checks per second per Remote Workspace. This is a stronger steady remote-idle wakeup candidate. [`src/ssh/control_connection.rs:735`](../src/ssh/control_connection.rs). Profile wakeups and disconnection detection before changing it; retain timely child-exit failure transition, authority revocation, and reconnect behavior. A process-exit notification mechanism could replace regular polling only if it has a reliable cancellation and cleanup path.

The reaper's unbounded channel accepts at most one cleanup ownership from its one child, so its nominal unbounded type does not by itself establish an unbounded workload backlog. [`src/ssh/process.rs:711`](../src/ssh/process.rs), [`src/ssh/process.rs:777`](../src/ssh/process.rs). Any consolidation must preserve process-group termination, bounded diagnostic retention, cancellation, ownership, and OpenSSH authentication semantics in [ADR 0003](../docs/adr/0003-let-openssh-own-remote-authentication.md).

## Measurement sequence

1. Establish `mise run build:release` and record the exact binary and revision. Keep the build outside capture windows. Use [the existing resource protocol](../docs/performance.md) and [the goal's acceptance conditions](performance-goal.md).
2. Add local, content-free stage markers for process entry, post-dependency capture, post-composition, GPUI start, first native frame, first terminal frame, and first usable shell. Mark SSH probe, Settings parse, font capture, home validation, and Pane construction separately. Keep instrumentation removable or behind an explicit local switch, and record its overhead. Do not log paths, environment values, terminal output, or credentials.
3. Repeat warm launches under fixed geometry, font, Settings, display scale, refresh rate, and shell configuration; label cold launches separately. Report medians, ranges, and first-frame versus usable-Pane times. A raw `ssh -V` sample is not an application launch measurement.
4. Sample 1, 4, and 16 idle Panes, active output per Pane, and close/reopen cycles. Capture application CPU, physical footprint, resident memory, wakeups, threads, file descriptors, and child process counts after settling. Sample the shell and SSH helper processes separately when total cost matters. For remote work, include connection and steady idle states.
5. Profile the selected hotspot before a change, then compare an optimized candidate against the same workload and output counts. Exercise local and remote failure paths, shell readiness, accessibility, graphics, hidden/unfocused visibility, and cleanup. Compare GPU work and residency with native tooling if a launch change affects rendering. Missing measurements remain explicitly unknown.

## Current recommendation

Instrument the launch stages first, with particular attention to complete SSH supervision and installed-font classification. The raw SSH command is short on this host, so a nontrivial async capability redesign is justified only if the full probe or its slow tail materially delays the first frame. The font scan has a concrete behavior-preserving reduction path: resolve the selected and default fallback families up front, and finish the full list before Settings first renders. Its actual cost is still unmeasured, so use stage timing as the selection gate. For remote idle energy, measure the 10 ms Control Connection supervisor first; it is a durable wakeup source. Keep Pane thread consolidation behind resource scaling evidence because its current ownership protects cleanup.

The selected-font candidate and its isolated measurements are recorded in [launch results](performance-launch-results.md). Application first-frame timing remains an open validation step.
