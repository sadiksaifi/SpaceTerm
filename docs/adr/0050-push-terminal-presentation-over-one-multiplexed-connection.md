# Push terminal presentation over one multiplexed connection

Each SpaceTerm Client holds one full-duplex SpaceTerm Protocol connection per SpaceTerm Server. Requests carry identities, so several can be in flight at once. The server pushes replies, terminal presentation, Pane events, native effect requests and Workspace Inventory as they happen, and no Pane waits for another Pane's work. The request-and-poll exchange it replaces spent most of a keystroke's latency inside SpaceTerm: a 30 ms output poll, one request at a time per connection, a WSS relay that slept whenever it was idle, and JSON screens of 18.5 KB per typed character. On wired Ethernet the network round trip was 0.7 ms of a 63 ms remote keystroke.

The connection writes terminal input ahead of presentation, and presentation ahead of bulk transfers such as Scrollback pages, images and large replies, which travel in bounded chunks, so a bulk transfer cannot delay a keystroke. Sockets disable Nagle's algorithm and keep the kernel send queue small, so this ordering happens in SpaceTerm's own outbox. Each frame is written whole.

Every message uses postcard in one length-prefixed framing, and no JSON travels on the wire. One encoding keeps one decoder and one set of bounds. The encoding spike measured postcard within 10% of a hand-written encoding. Mobile clients embed the same Rust client, so a text format would buy no portability. Screen rows travel as style runs against style and link tables that persist across a Pane's frames. The server hashes each row as it encodes it and reports a scroll as a shift when those hashes match the previous frame. It encodes only the rows the Terminal Emulator reports as damaged, without patching the engine.

The server keeps the authoritative screen and Scrollback of each Terminal Session. The client declares a maximum frame rate of 60 or 120 Hz for each Pane it shows. The server publishes the first output after idle immediately, then coalesces until output has been quiet for 4 ms, never faster than that rate, and respects synchronized output (DEC mode 2026). Each Pane has at most one unacknowledged frame, and newer state replaces pending state, so a slow client receives the latest screen rather than a backlog. Each frame reports the latest input it reflects. A hidden Pane receives no frames. A new Pane claim, a lost baseline or a reconnect receives a complete screen.

Each client keeps a Scrollback Cache for each Pane. It holds the rows the client received and the history pages it loaded. Wheel scrolling, Scroll Commands, Selection, copy and Terminal Find run over that cache, so they cost no round trip and keep each client's view independent under [ADR 0041](0041-keep-each-clients-view-independent.md). Opening Terminal Find loads older history in the background. A reconnect keeps the cache only when the Terminal Session and its history epoch are unchanged. While the program uses the alternate screen or mouse reporting, wheel and pointer input go to the program.

The server pushes Workspace Inventory as whole snapshots, and each new revision replaces any revision not yet written. Deltas wait until measurement shows a need for them. A shared edit takes one round trip: its reply carries the validated outcome after the revision that contains it, and acknowledging the outcome needs no reply. The client presents the edit optimistically under [ADR 0037](0037-resolve-shared-mutations-at-the-server.md), so the server keeps its disk syncs for durability and runs them off the request path. One server lock orders Pane state; encoding and disk syncs run outside it. The lock is split only if measurement shows contention. Lost replies, conflicts and reconnection keep the Original Operation rules.

Connection health comes from traffic and pings on the live connection, never from polling or extra connections. Silence or stalled writes end the connection, and the client recovers under [ADR 0045](0045-freeze-terminal-screens-while-reconnecting.md). After reconnecting, a Pane accepts input only once its control grant and a complete screen have been applied.

Account-local connections keep the Unix socket, because a shared-memory spike measured a gain under 0.1 ms. WSS runs TLS and the WebSocket directly on its TCP socket with readiness-driven I/O and no relay. Both sit behind one carrier interface, so a QUIC transport can replace TCP and WSS without changing messages. Admission, pairing, pinned certificates and proof keys are unchanged under [ADR 0027](0027-trust-paired-clients-equally.md) and [ADR 0028](0028-use-spaceterm-protocol-over-every-client-connection.md), and paired connections still cannot send server administration. Protocol failures carry typed classifications and bounded numbers, and decoders never echo input bytes.

Protocol major 2 replaces major 1 under [ADR 0035](0035-negotiate-one-protocol-major.md) and drops capability flags that every server already advertises. The admission preamble stays, so an incompatible peer still receives a typed incompatibility. The request-and-poll exchange, its WSS relay, its JSON screens and its polled presentation, inventory and native effects are deleted without compatibility.

This decision amends the exchange in ADR 0028, the protocol major in ADR 0035, the publication mechanism in [ADR 0036](0036-publish-workspace-changes-to-connected-clients.md), the resolution round trips in ADR 0037, the Scrollback reading in ADR 0041, and what renews recovery in ADR 0045. Pane control still follows [ADR 0022](0022-give-one-client-control-of-each-pane.md). QUIC, predictive local echo and any shared-memory path each need their own decision.
