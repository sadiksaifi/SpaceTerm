# Allow confirmed Tab closure across clients

An authorized SpaceTerm Client can close a Tab containing Panes controlled by another client after Close Confirmation. The confirmation states that the affected Terminal Sessions end for every client. [Pane control](0022-give-one-client-control-of-each-pane.md) governs input and dimensions, so the closing client does not need to take over those Panes first.

An idle Pane or Tab controlled by this client closes directly. The desktop asks when the Line Mode SpaceTerm Core last read for that exact Terminal Session shows a program other than the shell in the foreground, or when live shell integration shows a command running. A Terminal Session alone, missing or stale prompt metadata, and a shell still starting verify nothing. [The close facts](../../src/close_confirmation.rs) own this rule. An interrupted connection says nothing current, so it asks. Work controlled by another client always needs explicit confirmation. Kill Workspace always needs confirmation. Every shared close binds approval to the exact reviewed targets and live Terminal Sessions. Its confirmation names the Tabs, Panes and Terminal Sessions that end for every client, and says when the close removes the Workspace. Changed targets invalidate approval; optimistic removal under [ADR 0037](0037-resolve-shared-mutations-at-the-server.md) never broadens or renews it. A direct close also names this client's current control grants, which SpaceTerm Core rechecks at admission. A changed grant requires fresh review even when the Terminal Session is unchanged. A SpaceTerm Core without these facts requires explicit confirmation.

At admission, Core also checks for unanswered input and native processes that the close would end. This includes running, suspended, and disowned work in the terminal session. Core can skip confirmation for a process identified as a helper launched by the owning zsh's automatic `precmd` function.

Closing the last Pane closes its Tab. Closing the final Tab removes its Workspace and uses Workspace-level confirmation. The client activates another attached Workspace when one exists; otherwise it closes the Workspace Window and remains available in its menu bar or status area. Explicit Detach preserves Core-owned work and may leave an empty attachment view.

Close Tabs in a Worktree establishes a usable Tab outside the target Worktree before closing its Tabs. If fallback creation fails, the existing Tabs remain. This operation keeps Worktree files and branches; [ADR 0019](0019-create-and-remove-worktrees-by-running-git.md) owns their removal.
